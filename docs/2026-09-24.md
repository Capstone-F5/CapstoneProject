## 1. 대시보드 통계 전부 0 표시 수정

**원인**: `stats_dao.py` 전체 쿼리가 `Order.status == "COMPLETED"` 필터를 쓰고 있었음.
실제 주문은 직원이 수동으로 상태를 올리기 전까지 `RECEIVED` 상태에 머물러, 35건의 주문이 있어도 통계가 모두 0으로 표시됨.

**수정**: `_revenue_filter()` 도입.
- 조건: `Order.status != "CANCELLED"` + `Order.id IN (SELECT order_id FROM payments WHERE status="SUCCESS")`
- IN 서브쿼리를 써서 복수 결제 행이 있어도 집계가 중복되지 않도록 처리
- `get_today_summary`, `get_sales_series`, `get_popular_items`, `get_category_sales` 전부 적용
- 결제 수단 통계는 `Payment.status=="SUCCESS"` + `Order.status!="CANCELLED"` 기준 유지

## 3. 시리얼 포트 2개 동시 등록 불가 수정

**원인**: `requestPort()`를 같은 클릭 핸들러 안에서 두 번 호출 → 두 번째 호출에서 `SecurityError` 발생 (사용자 제스처 컨텍스트가 첫 번째 호출로 소모됨).

**수정** (`useSerial.js`):
- `requestPermission()` 1회 호출 = 포트 1개 등록. 2개 포트는 버튼을 두 번 누르는 방식으로 변경
- 자동 baud rate 탐지: `looksLikeGarbage()` (U+FFFD 비율)로 쓰레기 데이터 감지 → baud 전환
- `portBauds` Map으로 확인된 baud를 기억해 재연결 시 즉시 사용
- VID:PID 로그 형식: `1a86:7523@9600`
- `handlingRef`로 StrictMode 이중 마운트 방지
- 컨트롤 바에 `시리얼 N개` 표시 (portCount)

**Arduino 프로토콜** (cash_sorter 9600 / money_sorter 115200):
- `RESET COMPLETE` — 초기화 완료
- `INPUT=CARD` — 카드 버튼(D7/D8) 눌림
- `INPUT=NWON` — 현금 투입
- `INPUT=UNKNOWN` / `INPUT=RETRY` — 미인식 화폐
- `TOTAL:N` — money_sorter 합산 금액

**증상**: "결제가 완료되었습니다" 외 모든 TTS가 무음.

**3중 버그:**
1. **파일 미생성**: `generateCommonAudio.js`에 5개 터치 내레이션 문구 누락 → 스크립트 추가 후 mp3 13개 전부 생성
2. **SPA fallback 오인식**: Vite가 없는 mp3 경로에 `index.html`을 200으로 반환 → `ttsCache.js`에서 `Content-Type: audio/` 체크 추가
3. **StrictMode 이중 발화**: `_seq` 카운터로 stale 호출 자기종료 구현 (`tts.js`)

## 5. MediaPipe 제스처 커서 사라짐 수정

**원인 A** (커서 사라짐): `multiHandedness[i].score`는 좌우 판별 신뢰도이지, 검출 신뢰도가 아님. 손이 카메라 정면을 향하면 약 0.5로 떨어져 커서가 사라지는 현상 발생.
→ `handScore < 0.7` 게이트 완전 제거.

**원인 B** (커서 끊김): 한 손이 잡혔다가 Left↔Right 라벨이 뒤집히면 손별 히스테리시스 상태가 리셋되어 커서가 꺼짐.
→ 포인터 상태를 손별(`{Left, Right}`) 딕셔너리에서 단일 `let` 변수로 변경. 라벨 뒤집힘과 무관하게 유지.

**원인 C** (카메라 초기화 5초 지연): `hands.initialize()`를 명시 호출하지 않아 첫 `send()`가 WASM+모델 12MB 로딩을 떠안음.
→ `Promise.all([handsReady, cameraReady])`로 병렬 초기화. `initialize()` 선호출로 로딩 시간 카메라 열기와 겹침.

**원인 D** (StrictMode 충돌): StrictMode 이중 마운트로 `Hands` 인스턴스가 두 개 생성 → Emscripten `Module.arguments has been replaced` 어설션.
→ `await import('@mediapipe/hands')` 직후 `if (!active) return` 가드 추가.

## 6. MediaPipe 핀치 및 커서 정확도 저하 수정 (이번 세션)

**원인**: 이전 세션에서 검지 인식 민감도를 올리면서 임계값을 잘못 조정.

| 상수 | 변경 전 | 변경 후 | 문제 |
|---|---|---|---|
| `EXTENSION_MARGIN_POINT` | 1.08 | 1.04 | 검지 거의 안 펴도 포인팅 진입 |
| `EXTENSION_MARGIN_FOLD_ENTER` | 1.15 | 1.17 | 다른 손가락 반쯤 펴도 "접힘" 판정 → 거짓 포인팅 |
| `EXTENSION_MARGIN_FOLD_HOLD` | 1.18 | 1.22 | **핵심 범인**: 포인팅 종료 조건이 너무 관대 |

**핵심 로직**: `pinching = !pointing && _isPinching(...)` — 포인팅이 꺼지지 않으면 핀치 자체가 발동 불가.
FOLD_HOLD=1.22로 포인팅이 항상 ON → 핀치 완전 차단.

**수정**: `POINT 1.06`, `FOLD_ENTER 1.15`, `FOLD_HOLD 1.19` 로 복원 (완전 롤백이 아닌 이전 요청의 민감도 개선 의도를 살린 중간값).

## 7. YOLO 손가락 숫자 인식 추가

**모델**: `finger_count_best.pt` (yolo26n, 10 class: '0'~'9', mAP50=0.987)
- 수화 기호로 한 손 0~9 / 두 손 합산 최대 10+
- CPU i3-8100 기준 49ms/frame (imgsz=640)

**백엔드** (`ai_modules/cv/finger_counter.py`, `backend/api/finger_ws.py`):
- `/ws/finger` WebSocket: 바이너리 JPEG 수신 → `{"hands":[{"digit":N,"conf":0.94}],"total":N}` 반환
- `asyncio.Lock`으로 CPU 추론 직렬화 (다중 클라이언트 시 thread contention 방지)
- `get_detector()` 싱글톤 + `_warmup_finger_model()` 서버 시작 시 백그라운드 예열 (첫 연결 5초 대기 제거)

**프론트엔드** (`frontend/src/hooks/useFingerCount.js`):
- 응답 수신 후 다음 프레임 전송하는 response-driven 방식 (밀어 넣기 방지)
- 같은 숫자를 1초 유지해야 확정 (`HOLD_MS=1000`)
- `MISS_TOLERANCE=2`: 연속 2프레임까지 이탈 허용 (진행률 초기화 방지)
- 확정 후 1.5초 쿨다운 (`COOLDOWN_MS=1500`)
- 5초 무응답 워치독으로 루프 자동 복구

**App.jsx 연동**:
- `FINGER_SCREENS = new Set(['orderType', 'menu'])` — 해당 화면에서만 활성화
- 확정된 숫자 → `handleGesture({gesture: 'finger_N', ...})` 경로로 기존 제스처 로직 재사용
- 팝업: 노란 진행 바 + 숫자 표시
