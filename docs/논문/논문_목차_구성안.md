## 1. 7~9쪽 목표에 따른 구조 결정

초기 6장 구성(서론/관련연구/설계/구현/평가/결론 + 그림 6·표 5)으로 추산하면 **약 10쪽**이 되어 목표를 넘는다. 따라서 다음 두 가지를 적용한 **5장 구성**으로 확정한다.

1. **III. 시스템 설계와 IV. 시스템 구현을 「III. 제안 시스템」 한 장으로 통합** — 설계 의도와 구현 수단을 절 단위로 함께 서술하여 중복을 제거한다.
2. **그림 6개 → 4개, 표 5개 → 3개로 축소** — 그림 1개가 캡션 포함 약 0.3쪽을 차지하므로 분량 통제 효과가 가장 크다.

```
문제 제기(디지털 취약 사용자의 키오스크 장벽)
  → 기존 접근의 한계(시각적 단순화 / 단일 모달리티 / 근거 없는 생성)
  → 제안: 터치·음성·제스처 통합 + 데이터 근거화된 LLM 실행 + 보조기기 감지 기반 혼합형 적응
  → 제안 시스템(구조·상호작용·음성·비전) → 평가 프레임워크(3계층) → 결론
```

본 논문은 새로운 모델·알고리즘 제안이 아니라 **접근성 중심의 통합 시스템 설계·구현 논문**으로 포지셔닝한다. 실사용자 정량 평가는 수행 전이므로 IV장은 "실험 결과"가 아니라 **"평가 프레임워크 설계"**로 기술하고 효과 단정 표현을 배제한다.

### I. 서론 *(0.73쪽 · ✅ 완료 — 선행연구 문단 압축 검토 필요)*

5개 문단이 배경 → 한계 → LLM·RAG → 비전 → 목적·기여 순서를 충족한다. **II장이 작성되었으므로 2~4문단의 선행연구 서술은 한 문단으로 압축하고 상세 비교는 II장에 맡기는 정리가 남아 있다.** 이 압축으로 약 0.2쪽을 회수할 수 있다.

**기여 4항목(확정):** ① 터치·음성·제스처 통합 상호작용 구조, ② 실서비스 데이터에 연결된 LLM 도구 실행 구조, ③ 보조기기 감지 기반 능동 전환 + 사용자 재선택의 혼합형 적응, ④ 입력·과업·사용성 3계층 평가 프레임워크.

### III. 제안 시스템 *(약 2.0쪽 · 신규 작성 — 본 논문의 중심)*

**A. 설계 요구사항과 전체 구조** → **그림 1**
- 접근성 요구(입력 채널 선택 가능성, 상태 피드백, 조작 영역), 안전성 요구(상태 변경과 생성 응답의 분리), 개인정보 요구(영상 비저장)
- React(Vite) UI ↔ FastAPI/Uvicorn 백엔드 ↔ AI 모듈(STT/LLM/CV) ↔ DB
- 통신 분리: 주문·메뉴·결제는 REST(`backend/api/*`), 제스처·접근 감지는 WebSocket(`gesture_ws.py`, `approach_ws.py`) / 계층: `api` → `core` → `dao`

**B. 멀티모달 상호작용 모델과 모드 전환** → **그림 2**
1) 기본은 터치 모드
2) 흰 지팡이 감지 → 음성 안내·음성 모드 / 휠체어 감지 → 제스처 모드
3) 사용자의 직접 전환·해제 우선, 안내 종료 후 대상 이탈까지 재시작 잠금, 터치 시 즉시 종료
4) "맞춤형"의 정의: 생체 기반 자동 분류가 아닌 **능동 전환 + 명시적 선택의 혼합형 적응**
5) 접근성 화면 설계: 선택지 수 제한, 단계 표시, 아이콘+텍스트 병기, 4개 언어 실시간 전환

**C. LLM 음성 주문 파이프라인과 근거화된 실행** → **그림 3**, **표 2**
- Whisper STT → 발화 정규화·문맥 관리(`memory.py`, `session_context.py`, `action_context.py`) → 응답·TTS 스트리밍
- RAG: 메뉴·옵션·가격·할인 문서화 후 FAISS 인덱스, 데이터 변경 시 무효화·재구축 (`rag.py`)
- 도구 분리(**표 2**): 조회형 / 상태 변경형 / UI 제어형 (`action_tools.py`). 상태 변경은 도구 → 서비스 계층 → DB 경로로만 수행
- 모호·누락 발화에 대한 재질문과 결제 단계 제어(`checkout_progress.py`)

**D. 손동작 인식과 보조기기 감지** → **그림 4**, **수식 (1)**
- MediaPipe Hands 21개 랜드마크 → 손목 기준 평행이동·스케일 정규화 **(1)식**
- 정적 MLP(확인·손가락 개수) / 동적 MLP(손목 궤적 기반 상·하·좌·우 스와이프), 신뢰도 임계값 적용
- 검지 포인터 추적과 WebSocket 전달(`gesture_module_API.py`, `useGesture.js`)
- 보조기기 감지: 경량 객체 검출(TFLite int8, `approach_detector.py`)로 사람·흰 지팡이·휠체어 검출, 영상 비저장

**E. 구현 환경**
- 하드웨어·소프트웨어 버전·모델 구성을 **표가 아닌 본문 서술**로 처리(분량 절감)

### IV. 평가 프레임워크 *(약 0.8쪽 · 신규 작성)*

> 실험을 일부라도 수행하면 장 제목을 "IV. 실험 및 평가"로 바꾸고 수행분만 결과로 기술한다.

- **A. 평가 설계 원칙** — 기능의 존재가 아니라 과업 완수를 측정, 터치 전용 조건과 멀티모달 조건의 비교 설계
- **B. 3계층 지표** → **표 3**
  - 계층 1 입력 인식: STT WER/CER, 도구 호출 정확도, 근거성·장바구니 무결성, 제스처 오인식률, 보조기기 감지 F1·오전환율
  - 계층 2 과업 수행: 성공률, 완료 시간, 재시도·도움 요청, 구간별 지연시간
  - 계층 3 주관적 사용성: SUS 또는 PSSUQ, 채널 선택 이유 인터뷰
- **C. 연구 윤리 및 개인정보** — 동의 절차, 영상·음성 비저장 및 비식별화, 삭제 정책

5. **최종 점검** — 인용 누락, 그림·표 규격, 금지 표현 검사.
