## 1. 프로젝트와 논문 양식의 기준

### 1.1 프로젝트 README 기준의 시스템 범위

프로젝트는 디지털 약자를 위해 음성 및 제스처 중심의 배리어프리 키오스크를 구현하는 것을 목표로 한다. README에 기재된 주요 구성은 다음과 같다.

- **음성 상호작용**: OpenAI Whisper 기반 음성 인식, LLM을 이용한 자연어 정규화 및 의도 해석, LangChain 기반 대화 문맥 관리, 음성 응답 및 토큰 스트리밍.
- **비접촉 제스처 상호작용**: MediaPipe Hands의 손 랜드마크를 이용한 손 인식, WebSocket 기반 실시간 전달, 상·하·좌·우 스와이프, 확인 동작, 손가락 개수, 검지 포인터 등.
- **다중 모드 접근성**: 터치·음성·제스처 입력, 화면 포인터와 레이블, 한국어·영어·중국어·일본어 지원을 고려한 UI.
- **소프트웨어 구조**: React 기반 프런트엔드, FastAPI/Uvicorn 기반 백엔드, WebSocket 및 REST 통신, OpenCV·MediaPipe·Whisper·LLM·LangChain·SQLite 활용.

후속 원고에서는 위 내용을 “프로젝트의 설계 목표 및 구현 범위”로 사용하되, 실제 동작 여부와 실험 결과는 현재 코드 및 실험 로그를 다시 확인한 뒤 확정해야 한다. 특히 음성 인식 정확도, 제스처 인식 정확도, 응답 지연시간, 사용자 평가 결과는 문헌의 수치를 프로젝트 결과처럼 사용해서는 안 된다.

### 1.2 한국실천공학교육학회 논문지 양식에서 확인한 작성 포인트

- 국문 제목과 영문 제목을 함께 제시한다.
- 요 약과 ABSTRACT를 별도 구성한다.
- Key Words는 영문으로 작성하며, 최종 원고에서는 5개 이내로 정리한다.
- 본문은 I. 서론, II. ...와 같은 장 번호를 사용하고, 하위 항목은 A., 1) 체계로 구성한다.
- 참고문헌은 영문 형식과 번호 인용을 사용하므로, 현재 노트의 [R01] 형식은 최종 원고에서 [1], [2] 형식으로 변환한다.
- 제목·초록·서론에서는 구현 세부사항을 모두 나열하기보다, **사회적 문제 → 기존 키오스크의 한계 → 선행기술의 시사점과 한계 → 제안 시스템의 통합 방향 → 논문의 기여** 순서로 압축하는 것이 적절하다.

## 2. 문헌 전체에서 반복되는 핵심 논점

### 2.1 키오스크 확산과 디지털 접근성 문제

여러 연구는 키오스크가 인력 절감과 서비스 자동화를 촉진하지만, 고령자·시각장애인·신체장애인·아동·디지털 기기 사용이 익숙하지 않은 사용자에게는 새로운 장벽이 될 수 있다고 설명한다. 장벽은 단순히 글씨 크기가 작다는 문제에 국한되지 않는다.

- 다음 단계나 현재 위치를 이해하기 어렵다.
- 메뉴와 선택지가 한 화면에 과도하게 제시된다.
- 버튼의 의미, 뒤로 가기, 이전·다음 단계가 명확하지 않다.
- 오류나 입력 성공에 대한 피드백이 부족하다.
- 터치 정확도, 시선 이동, 자세, 휠체어 높이와 같은 신체 조건이 고려되지 않는다.
- 주변 소음 때문에 음성 입력이 실패할 수 있다.
- 시각적 확대만으로는 긴 문장과 복잡한 정보 구조에서 발생하는 인지 부담을 해결하지 못한다.

따라서 배리어프리 키오스크는 “큰 글씨를 제공하는 화면”이 아니라, 사용자가 자신의 방식으로 서비스 목표를 달성할 수 있도록 입력 방식·정보 구조·피드백·화면 배치를 함께 조정하는 시스템으로 정의하는 것이 좋다.

### 2.2 시각적 단순화는 중요하지만 단독 해결책은 아니다

고령자 대상 KORAIL 키오스크 연구와 미술관 현장 연구는 시각적 재설계, 기능 축소, 단계 표시, 명확한 레이블, 일관된 버튼 배치가 작업 성공률과 만족도에 긍정적임을 보여준다. 반면 단순히 화면을 확대하거나 고대비로 바꾸는 것만으로는 정보 구조와 인지 부담을 해결할 수 없다.

특히 미술관 현장 연구에서는 배리어프리 버전이 화면 가독성과 신체적 부담을 줄였지만, 긴 설명과 복잡한 정보 연결 때문에 정보 탐색 과업에서 여전히 어려움이 관찰되었다. 이는 본 프로젝트의 UI 설계에서 다음 요소를 함께 고려해야 함을 의미한다.

- 한 화면의 핵심 선택지 수 제한
- 짧고 쉬운 표현
- 현재 단계와 남은 단계 표시
- 버튼을 누른 뒤의 시각·음성·촉각 피드백
- 아이콘만 또는 색상만 사용하지 않는 레이블 설계
- 사용자 상황에 맞춘 화면 모드와 글자 크기
- 휠체어 사용자나 신장이 작은 사용자를 고려한 조작 영역 배치

### 2.3 음성은 접근성을 넓히지만, 음성만으로는 충분하지 않다

음성 기반 키오스크 연구들은 터치 조작이 어려운 사용자에게 자연어 입력이 대안이 될 수 있음을 보여준다. 그러나 음성 입력은 다음 조건에 크게 영향을 받는다.

- 주변 소음과 키오스크 간 거리
- 사용자의 발음·억양·방언·말 빠르기
- 메뉴명과 실제 발화의 차이
- 한 문장에 여러 주문 조건을 포함하는 복합 발화
- 음성 인식 결과의 오탈자와 조사·어미 변형
- 음성 입력이 처리되었는지 사용자가 알 수 있는 피드백 부족

따라서 단순한 STT 결과를 곧바로 메뉴 검색에 사용하는 것보다, 음성 입력 → STT → 오탈자·표현 정규화 → 의도·개체 추출 → 누락 정보 확인 → 메뉴/장바구니 도구 실행 → 음성·화면 피드백의 단계가 필요하다. 이 구조는 프로젝트의 Whisper와 LLM 기반 자연어 처리, 장바구니·메뉴 API 연동을 설명하는 근거로 활용할 수 있다.

또한 KORAIL 연구에서 음성 기능을 추가했음에도 도움 요청이 오히려 늘어난 조건이 관찰되었다. 음성의 존재 자체보다 인식 품질, 주변 환경, 입력 결과의 가시화가 중요하다는 의미이다. 최종 논문에서는 “음성으로 모든 접근성 문제가 해결된다”고 쓰기보다, 음성을 터치·제스처와 함께 제공하는 보완적 입력 채널로 서술하는 편이 타당하다.

### 2.4 LLM은 대화와 자연어 유연성을 높이지만, 근거 연결이 필요하다

GPT 기반 키오스크 연구는 정형화된 버튼 선택 대신 사용자가 자연어로 요청할 수 있다는 가능성을 제시한다. MCP 기반 행정 키오스크 연구는 필요한 정보를 한 항목씩 질문하는 단계적 입력 수집을 구현하여, 복잡한 행정 서비스에도 대화형 인터페이스를 적용하였다.

그러나 LLM은 다음과 같은 위험이 있다.

- 존재하지 않는 메뉴나 가격을 생성할 수 있다.
- 메뉴 데이터나 운영 정책이 변경되어도 학습 지식이 자동으로 갱신되지 않는다.
- 사용자의 짧거나 모호한 발화를 잘못 해석할 수 있다.
- 도구 실행 전에 확인 절차가 없으면 잘못된 주문·결제로 이어질 수 있다.

RAG 관련 연구는 외부 지식 저장소에서 관련 문서를 검색해 LLM의 응답 문맥으로 제공하는 구조를 제안한다. 키오스크에서는 메뉴·옵션·알레르기 정보·운영 정책을 데이터베이스 또는 검색 저장소와 연결하고, 최종 주문·결제는 허용된 API 또는 도구 호출로 제한하는 방식이 적절하다. 이때 RAG는 “LLM이 메뉴를 기억하게 하는 기술”이라기보다, **현재 시스템 데이터에 응답을 근거화하고 생성 범위를 통제하는 구조**로 설명할 수 있다.

### 2.5 컴퓨터 비전은 맞춤형 UI와 비접촉 조작을 가능하게 한다

관련 연구는 크게 두 방향으로 나뉜다.

1. 카메라로 사용자의 자세·휠체어·지팡이·연령·시선·얼굴 상태 등을 추정해 UI를 조정하는 방식
2. 손 또는 신체 동작을 인식해 터치 없이 화면을 조작하는 방식

MediaPipe 기반 연구와 손동작 키오스크 연구는 실시간 스트리밍, 손 랜드마크, 동작 분류를 이용한 비접촉 입력의 기술적 타당성을 보여준다. 프로젝트의 MediaPipe Hands 기반 제스처 모듈은 이 계열의 연구를 최신 실시간 웹 시스템으로 확장하는 위치에 놓을 수 있다.

반면 얼굴·연령·성별·감정·장애 여부를 추정해 사용자를 분류하는 방식은 성능뿐 아니라 개인정보, 편향, 오분류의 영향까지 고려해야 한다. 연령이나 장애를 영상으로 판단해 사용자를 자동 분류하는 것을 배리어프리의 필수 조건처럼 서술해서는 안 된다. 최종 원고에서는 가능하면 사용자가 직접 선택하는 접근성 모드, 비식별화된 동작 정보, 최소 수집 원칙을 우선 제시하고, 카메라 기반 추정은 보조 기능 또는 연구 한계로 명확히 구분하는 것이 안전하다.

### 2.6 실제 사용자 평가가 연구의 핵심 병목이다

선행연구의 평가 방식은 크게 네 가지로 구분된다.

- 인식·분류 정확도: STT/의도/개체, 얼굴·자세·손동작
- 과업 성능: 성공률, 부분 성공, 소요 시간, 클릭 수, 도움 요청 수
- 사용성·만족도: SUS, PSSUQ, 5점 또는 7점 척도, 인터뷰
- 접근성·상호작용 분석: 시선 경로, 오류·되돌리기, 화면별 이탈, 피드백 이해 여부

문헌에서 반복되는 한계는 실제 사회적 약자 표본이 작거나, 합성 데이터·시뮬레이션에 의존하거나, 특정 장소와 특정 메뉴만 평가했다는 점이다. 따라서 본 프로젝트의 실험을 설계할 때는 단순히 “인식률이 높다”는 결과뿐 아니라, 사용자가 실제 주문 또는 서비스 목표를 완수했는지와 어떤 입력 채널에서 어려움이 줄었는지를 측정해야 한다.

권장 지표는 다음과 같다.

- 과업 성공률 및 부분 성공률
- 과업 완료 시간
- 재시도·되돌리기·취소 횟수
- 도움 요청 횟수
- 음성 인식 및 의도/개체 추출 정확도
- 제스처 인식 정확도와 오인식률
- 응답 지연시간
- 사용자 만족도 및 주관적 사용성
- 오류 발생 지점과 화면별 이탈

## 3. 연구 공백과 본 논문의 위치

### 3.1 선행연구에서 확인되는 공백

문헌을 종합하면 다음과 같은 공백이 남아 있다.

1. 많은 연구가 시각적 UI 개선, 음성 입력, 제스처 입력, 사용자 분류 중 한 가지 기능에 집중한다.
2. LLM 기반 키오스크 연구는 자연어 대화 가능성을 제시하지만, 실제 사용자 평가나 오인식·복합 주문·도구 실행 안전성 검증이 부족하다.
3. 음성 키오스크 연구는 의도 분류 기반 구조가 많고, 최신 LLM을 활용한 표현 정규화와 문맥 기반 확인 절차는 충분히 다루지 않았다.
4. 컴퓨터 비전 기반 맞춤형 UI 연구는 연령·성별·장애 추정의 개인정보와 편향 문제를 충분히 논의하지 않거나, 합성 데이터·소규모 데이터에 의존한다.
5. 제스처 기반 비접촉 키오스크 연구는 기술 시연에 그치는 경우가 많고, 고령자·장애인 사용자의 실제 과업 수행 효과를 검증한 연구가 적다.
6. 음성, 제스처, 터치가 함께 제공되는 다중 입력 구조에서 사용자가 어떤 상황에 어떤 채널을 선택하는지에 대한 비교 평가가 부족하다.
7. RAG 또는 데이터베이스 연결을 사용하더라도, 메뉴·옵션·가격·주문 실행 사이의 근거성과 오류 복구를 사용자 관점에서 평가한 연구가 부족하다.

### 3.2 본 프로젝트를 논문에서 포지셔닝하는 방법

본 논문은 “새로운 LLM 자체” 또는 “새로운 손동작 분류 알고리즘”을 제안하는 논문으로 포지셔닝하기보다, 다음과 같이 **접근성 중심의 통합 시스템 설계·구현**으로 설명하는 것이 적절하다.

- 자연어 표현이 다양하고 불완전해도 처리할 수 있는 LLM 기반 음성 대화
- 메뉴·장바구니·주문 기능과 연결되는 제한된 도구 실행 구조
- 손가락·스와이프·확인 동작을 통한 비접촉 입력
- 터치·음성·제스처를 상호 보완적으로 사용하는 다중 모달 UI
- 사용자의 조작 부담을 줄이는 화면 구조와 피드백
- 실제 과업 성능과 접근성 지표를 중심으로 한 평가

초록과 서론에서 아직 실험 결과가 확정되지 않았다면 “향상시켰다”라고 단정하지 말고, “설계·구현하고 평가하고자 한다”, “검증을 위한 평가 지표를 구성하였다”와 같이 실제 결과의 범위에 맞춰 표현해야 한다.

- **한계 및 주의**: 정확한 수치와 실제 장애·고령 사용자 평가가 충분하지 않다. 미디어 아트·위생 목적의 비접촉 조작과 사회적 약자 접근성은 동일한 연구 목표가 아니다.
- **이번 논문에서의 활용**: MediaPipe 기반 비접촉 동작과 단순 제스처 설계의 사례로 사용한다. 본 프로젝트에서는 동작 종류를 최소화하고, 제스처 오인식 시 터치·음성으로 전환하는 오류 복구를 강조한다.
- **페이지**: 전체 pp.1–4.

## 6. 요약·ABSTRACT·서론 작성에 바로 사용할 논리 구조

### 6.1 요약에 들어갈 요소

최종 요약은 다음 네 문장을 중심으로 압축할 수 있다.

1. **문제**: 무인 키오스크의 확산에도 불구하고 고령자·시각장애인·신체장애인·디지털 취약 사용자는 화면 중심·단일 입력·복잡한 절차로 인해 서비스 이용에 어려움을 겪는다.
2. **방법**: 본 연구는 LLM 기반 음성 대화와 MediaPipe 기반 비접촉 제스처를 터치 입력과 함께 제공하고, 메뉴·장바구니·주문 기능을 백엔드 서비스와 연결하는 배리어프리 키오스크를 설계·구현한다.
3. **핵심 설계**: 음성 발화의 정규화·문맥 처리·단계적 확인, 손동작 기반 화면 이동·선택, 큰 레이블·단순화 화면·상태 피드백을 통합한다.
4. **검증**: 실제로 수행한 경우에만 과업 성공률, 완료 시간, 오류·도움 요청, 음성·제스처 인식률, 응답 지연 및 사용성 결과를 보고한다. 아직 실험 전이라면 “평가하고자 한다”로 쓴다.

### 6.2 ABSTRACT에 들어갈 요소

영문 ABSTRACT는 국문 요약과 주장 범위를 일치시킨다. 다음 키워드를 영문으로 변환해 작성할 수 있다.

- barrier-free kiosk
- vulnerable users
- large language model
- computer vision
- multimodal interaction

최종 Key Words는 양식의 개수 제한에 맞춰 5개 이하로 확정하고, 알파벳순 정렬 여부를 양식과 대조한다. “socially disadvantaged”는 의미가 넓고 다소 부자연스러울 수 있으므로, 문맥에 따라 digitally vulnerable users, older adults, users with disabilities 중 정확한 표현을 선택한다.

### 6.3 서론의 권장 전개

#### A. 연구 배경

- 비대면·무인 서비스 확산과 키오스크의 역할
- 고령자·장애인·디지털 취약 사용자가 겪는 화면·입력·절차 장벽
- 기존의 큰 글씨·고대비·기능 축소 접근의 의미와 한계

#### B. 선행연구와 한계

- 고령자용 UI 및 사용성 평가 연구: R10, R21
- 음성·대화형 키오스크 연구: R09, R13, R16, R23
- LLM·RAG 기반 서비스 연구: R04, R12, R18
- 비전·제스처·맞춤형 UI 연구: R02, R07, R20, R22, R24, R25
- 선행연구가 단일 모달리티, 제한된 도메인, 소규모·합성 데이터, 실제 사용자 평가 부족이라는 공통 한계를 갖는다는 점

#### C. 연구 목적과 기여

- LLM 음성 대화, 컴퓨터 비전 제스처, 터치 UI를 하나의 키오스크 시스템에 통합
- 메뉴·장바구니·주문이라는 실제 서비스 흐름과 자연어 상호작용 연결
- 입력 실패·모호한 발화·제스처 오인식에 대한 확인 및 대체 입력 제공
- 접근성 기능의 존재가 아니라 실제 과업 수행을 평가할 수 있는 지표 제시

### 6.4 서론에서 피해야 할 표현

- “모든 사회적 약자가 사용할 수 있다”: 사용자군과 평가 범위를 벗어난 과장이다.
- “LLM이 사용자의 의도를 정확히 이해한다”: 실험 수치와 오류 분석 없이는 단정할 수 없다.
- “얼굴 인식으로 장애 여부를 판단한다”: 개인정보·편향·윤리 문제가 크므로 신중하게 다룬다.
- “RAG로 환각을 제거한다”: RAG는 근거성을 높일 수 있지만 검색 오류와 생성 오류가 남는다.
- “제스처만으로 터치 없이 완전한 접근성을 제공한다”: 시각·운동·인지 특성이 다른 사용자에게 입력 방식은 선택 가능해야 한다.
- 문헌의 정확도나 사용성 점수를 프로젝트 결과처럼 서술한다.

## 7. 최종 원고 작성 전 확인할 실험 항목

문헌 요약을 본 프로젝트 결과로 전환하기 전에 다음 항목을 실제 구현 및 실험으로 확인한다.

| 확인 항목 | 최소 기록 내용 |
|---|---|
| 음성 인식 | 발화 수, 소음 조건, STT 오류 유형, 인식률 또는 의도·개체 정확도 |
| LLM 처리 | 정규화 성공률, 모호한 발화 재질문률, 잘못된 도구 호출, 응답 시간 |
| RAG·메뉴 연결 | 검색 성공률, 근거 없는 메뉴 응답, 최신 데이터 반영 여부 |
| 제스처 | 동작별 정확도·오인식률·검출 지연, 조명·배경 조건 |
| 과업 수행 | 주문 성공률, 완료 시간, 재시도·뒤로 가기·도움 요청 횟수 |
| UI 접근성 | 글자·버튼 크기, 대비, 단계 안내, 상태 피드백, 화면 모드 |
| 사용자 평가 | 참가자 특성, 과업, 비교 조건, 사용성 척도, 윤리·동의 절차 |
| 개인정보 | 카메라 영상 저장 여부, 음성 저장 여부, 비식별화, 삭제 정책 |
