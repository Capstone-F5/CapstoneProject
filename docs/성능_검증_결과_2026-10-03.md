세부 분석은 `docs/음성_시나리오_테스트_결과_W100.md`, `docs/음성_시나리오_테스트_결과_104_2026-10-03.md`.

### 3.2 고정 100개 Full 테스트 — 98/100

| 항목 | 값 |
|---|---|
| 통과 | 98/100 (시나리오), 1,106/1,112턴 (99.5%) |
| 실패 | W006 — OpenAI `ReadTimeout`(코드 문제 아님), W089 — `set_qty` 턴 |
| 소요 | **461초** (이전 `--workers 3`·`localhost` 사용 시 3,696초 → 약 8배 단축) |
| 묶음 | 기본 다품목 25, 편집 30, 세트 옵션 25, 종합 20 |

W089 실패 내용: 「게살버거 단품 1개로 바꿔줘」(수량을 1개로 지정)에 모델이 수량을 바꾸지 않고 `add_item`으로 **1개를 더 담음**(기대 ×1, 실제 ×3). 가드 개입 없음.
"X 단품 N개로 바꿔줘"를 직접 명령으로 처리하면 해결될 가능성이 높으나 아직 구현하지 않았다.

측정 이력(같은 100개): 53 → 56 → 86 → 94 → (실패 6개 보강 후 6/6) → **98/100**.

### 3.3 랜덤 30개 검증 (시드 7) — 27/30

| 항목 | 값 |
|---|---|
| 통과 | 27/30 (90%), 318/328턴 (97.0%) |
| 실패 | R7-08, R7-09, R7-25 (모두 `세트 옵션` 묶음) |
| 소요 | 151초 |
| 타임아웃·연결 오류 | 0 |

| 시나리오 | 실패 턴 | 원인 |
|---|---|---|
| R7-08 | 「치킨다릿살버거 세트 양배추 빼주세요」 | 모델이 `update_item`을 호출하고 "양배추를 제외했습니다"라고 답했으나 **제외 옵션이 장바구니에 반영되지 않음** |
| R7-09 | 「더블불고기버거 세트 양파 빼주세요」 | 같은 유형 — 제외 옵션이 **다른 줄(치즈버거)에 붙음** |
| R7-25 | 「콜라로 주세요」(세트 옵션을 여러 턴에 걸쳐 고르는 중) | `update_item`과 `add_item`이 함께 호출돼 같은 세트 줄의 수량이 늘고(×3) 옵션이 섞임. 같은 메뉴의 세트가 장바구니에 이미 있는 상태에서 발생 |

R7-08·R7-09는 "세트 재료 제외" 한 가지 유형이라 직접 명령으로 옮기면 고칠 수 있다(아직 구현하지 않음).
이전 랜덤 30개(시드 2026)는 28/30이었고, 그 실패 2개는 이번 작업에서 수정해 R2026-21 통과, R2026-24는 타임아웃으로 확인되지 않았다(수정 전 측정이라 이번 결과와 직접 비교하지 않는다).

## 5. 응답 시간 (가드 개입별)

`python tools/latency_report.py <결과 json>` 집계. 서버에 텍스트가 들어가서 나올 때까지의 시간이며 STT·TTS·VAD는 포함하지 않는다.

| 분류 | 100개 Full: 턴 수 | 중앙값 | P95 | 랜덤 30개: 턴 수 | 중앙값 | P95 |
|---|---|---|---|---|---|---|
| 전체 | 1,112 | 2,174ms | 5,024ms | 328 | 2,206ms | 5,518ms |
| 직접 처리(direct, LLM 없음) | 237 (21%) | 178ms | 389ms | 63 (19%) | 173ms | 301ms |
| 가드 거절(blocked) | 37 (3%) | 4,589ms | 6,890ms | 7 (2%) | 5,558ms | 10,503ms |
| 가드 보정(fixed) | 36 (3%) | 2,478ms | 4,060ms | 12 (4%) | 2,692ms | 5,935ms |
| 개입 없음 | 802 (72%) | 2,540ms | 5,034ms | 246 (75%) | 2,524ms | 5,291ms |

- 직접 처리는 LLM을 거치지 않아 중앙값 약 0.2초, LLM 턴(약 2.6초)의 1/14.
- 가드가 도구를 거절해 모델이 재시도한 턴은 개입 없는 LLM 턴보다 중앙값 +2.0초(100개)·+3.0초(랜덤 30개).
- `localhost`→`127.0.0.1` 수정 전(이 PC에서 연결당 약 2초 지연)에는 전체 중앙값이 약 4.5초였다. 이후 측정과는 환경이 달라 직접 비교하지 않는다.
- 동시 실행 6에서도 ReadTimeout은 100개 중 1건(W006), 랜덤 30개에서는 0건이었다.

## 7. 한계와 해석 주의

1. **고정 100개·기존 104개는 튜닝에 쓴 시나리오다.** 98%·104/104는 상한에 가깝고, 처음 보는 입력에 대한 기대치는 랜덤 30개의 90%(표본 30개라 신뢰구간이 넓다)가 더 적절하다.
2. 랜덤 30개는 한 번만 실행했다. 모델 응답이 실행마다 달라질 수 있어 같은 시드를 다시 돌리면 결과가 1~2개 달라질 수 있다(`temperature=0`이지만 완전한 결정성은 보장되지 않음).
3. 이 수치는 **텍스트 입력 기준**이다. 음성 인식(STT) 오류, 에코, 배경 소음, 실제 마이크·스피커 지연은 포함하지 않는다. 실제 음성 단계 지연은 `backend/logs/voice_timing.log`에 기록되나 집계하지 않았다.
4. Raspberry Pi 실기기, 지팡이·휠체어 감지, 제스처 인식 성능은 이 문서에 없다(측정하지 않음).
5. 시나리오는 한국어 위주이며(영어 시나리오 일부 포함) 일본어·중국어 흐름의 정확도는 따로 측정하지 않았다.
