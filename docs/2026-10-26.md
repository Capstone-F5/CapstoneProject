### 1-1. 결제·주문 정확성
| 문제 (로그 근거) | 원인 | 수정 |

| "아니, 그냥 결제해줘"에 단품이 또 담김 (10-13, 15,600원) | 주문 보충 로직이 "그냥"을 단품 신호로 읽음 | 결제 의사가 있는 발화에서는 주문 보충을 건너뜀 (`llm_service._complete_missing_order`) |

| 손님이 번호를 말한 적이 없는데 모델이 11자리를 지어냄 (검증 실행 중 발견) | 이번 발화에 숫자가 없으면 번호 검증을 건너뜀 | 이번·최근 발화에 번호가 없으면 `points_phone` 거부 (`action_tools.ui_action`) |
| "결제페이지 이동해줘"가 간편결제로 읽힘 (10-26) | "페이지"의 "페이"가 간편결제 키워드에 매칭 | 키워드 매칭 전에 "페이지"·"payment" 제거 |
| 이미 그 화면인데 `navigate` 액션과 "이동했습니다" 응답 | 현재 화면 정보가 툴에 없었음 | `action_context.get_screen` 추가, 같은 화면 이동 무시, 응답을 "이미 ~ 화면이에요"로 교정 (`guards.fix_screen_reply`) |
| 시작 화면에서 "좋은 시작!"(= "주문 시작" 오인식)에 "결제 진행할까요?" | 화면 문맥 무시 | 시작 화면에서 결제·장바구니 응답이 나오면 주문 시작 안내로 교체 |

### 1-2. 음성 인식·무응답
| 문제 | 수정 |
|---|---|
| 도메인 어휘 없는 발화가 `noise`로 판정돼 **응답 없이** 버려짐 ("대전에서 먹을게", "철제.", "갑자기 왜 이게 떠?") | 응답을 기다리는 화면(`orderType`/`menu`/`cart`/`payment`)에서 공백 제외 14자 이하이면 "잘 못 들었어요. 다시 한번 말씀해 주세요"로 재질문 (`llm_service._should_reprompt_noise`) |
| STT 오인식: "정립할게"(적립), "대전에서 먹을게"(매장에서) | `guards._STT_FIXES`에 문맥 조건부 교정 추가 |
| "지금 뭐 담겼어?"가 노이즈로 막힘 (검증 실행 중 발견) | 도메인 어휘에 "담겼/담겨/담긴/담았" 추가 |
| `short_word_logprob_threshold` 설정이 무시되고 코드 상수가 쓰임 | 설정값을 실제로 사용, 짧은 단답 완화 통과는 `stt_quality.log`에 `reason=short_pass` 기록 |

### 1-3. 알레르기 (안전)
- 10-06 로그: "갑각류 알레르기 있으면 못 먹는 버거가 있어?"에 "없습니다"라고 틀리게 답함, 대두 알레르기 손님에게 대두가 든 메뉴를 추천.
- **DB 기반 응답**: `GET /api/menu/allergens`(신규)로 알레르기 마스터를, `/api/menu`의 `allergens`로 메뉴별 성분을 읽어 코드가 직접 계산해 답합니다 (`ai_modules/llm/allergy.py`). 성분 이름은 코드에 두지 않고 DB `name_ko`를 기준으로 합니다.
- **있다/없다 판단**: 규칙이 단순한 경우("갑각류 알레르기 있어")는 바로 확정하고, 부정만 있으면("없어요") 기억하지 않습니다. 있다/없다가 섞였거나 성분 이름을 못 찾으면 LLM이 마스터 코드로 변환합니다 (`OPENAI_ALLERGY_TIMEOUT`, 기본 8초). 마스터에 없는 코드는 버립니다.
- 손님이 밝힌 알레르기 성분이 든 메뉴를 **이름을 말하지 않고** 담으려 하면 `allergy_conflict`로 막습니다.
- 한계: 시드(`backend/core/seed.py`)의 알레르기 값은 "재료 설명 기반 추정"이라고 주석에 적혀 있습니다. 코드가 이 값으로 직접 답하므로 운영 전 실제 레시피 기준 검증이 필요합니다. 동의어 표(`_SYNONYMS`, "갑각류"=새우+게 등)는 DB에 없는 정보라 코드에 남아 있습니다.

### 1-4. 장바구니 응답
- 요청의 `cart`가 비어 오면 서버 장바구니로 대신 답함 (`_cart_for_status_reply`).
- 한국어 장바구니 안내를 TTS 친화적으로 변경: `x1`, 괄호 나열 → "F버거 세트 하나가 담겨 있어요. 사이드는 …, 음료는 …" (`cart_context._spoken_cart_reply_ko`).

### 1-5. 교체·수량 변경·삭제 (음성 검증에서 가장 많이 틀린 조작)
첫 측정(50개)에서 시나리오별 첫 실패 36건 중 **30건이 교체("A 말고 B로", "A 취소하고 B 줘")**였습니다.
서버 동작: 삭제만 하고 되묻기 19회 / 삭제+담기 16회 / 변경+추가 담기 8회(중복·불일치).

- `cart_commands`에 두 명령을 LLM 없이 처리하도록 추가했습니다.
  - `replace`: "A 말고/취소하고/대신 B 단품으로 바꿔줘". 새 메뉴를 먼저 담고 지우며(담기 실패 시 장바구니 불변), 수량은 A의 수량을 따릅니다. B가 세트이거나 대상이 하나로 정해지지 않으면 LLM이 되묻도록 `None`을 돌려줍니다.
  - `set_qty`: "X N개로 바꿔줘". 세트 줄은 옵션을 유지한 채 수량만 바꿉니다.
- **데이터 손실 방지**: "F버거 세트 5개로 바꿔줘"에 모델이 **무관한 줄을 삭제**한 사고(R15). `guards._REMOVE_INTENT`가 "바꿔줘"를 삭제 의사로 읽던 것이 원인이었습니다.
  `remove_item`이 순수 삭제어(`has_pure_remove_intent`)를 요구하고, 손님이 말한 메뉴와 다른 줄이면 `remove_wrong_target`으로 막습니다.
- **전화번호 폴백**: 적립을 선택한 뒤 손님이 010으로 시작하는 10~11자리를 말했는데 모델이 `points_phone`을 보내지 않으면 직접 보냅니다 (`intent_fallback`). "전화번호를 확인했습니다"라고만 하고 액션이 없으면 응답을 교정합니다 (`guards._CLAIM_PHONE`).

### 1-6. 지연·로깅
- 10-13의 STT `sttMs=55,494ms`(발화 2.4초)는 로컬이 아니라 OpenAI API 지연이었고, `AsyncOpenAI`/`ChatOpenAI` 모두 timeout·재시도를 지정하지 않아(SDK 기본 10분, 재시도 2회) 길어질 수 있었습니다.
  STT는 `OPENAI_STT_TIMEOUT`(기본 15초), LLM은 `OPENAI_LLM_TIMEOUT`(기본 30초), 재시도 1회로 제한했습니다. STT API가 8초를 넘기면 경고 로그를 남깁니다.
- `voice_timing`의 `path`에 `noise`/`allergy`/`cart_query`/`direct`/`checkout`/`error`를 구분해 기록합니다(`llmMs=null` 원인 추적).
- 마이크 게이트(`frontend/src/utils/audioGate.js`)에 짧은 충격음 구제 옵션 `impulseRescue`를 추가했으나 **기본 꺼짐**입니다. 합성 클립 시험에서 짧은 단어 후보와 박수가 현재 지표로는 구분되지 않았습니다.

## 2. 검증 도구

| 도구 | 내용 |
|---|---|
| `backend/tools/flow_scenarios_gen.py` | 랜덤 흐름 생성기. `--human 0\|1\|2`로 말투 변형(군말, 서버가 교정하는 STT 오인식), `--tier 사람처럼` 티어 추가. **기본 생성 결과는 기존과 동일**(고정 100개·랜덤 40개를 수정 전 코드와 비교해 확인) |
| 사람처럼 티어 조작 | `change_mind`(교체), `ask_mid_order`(질문 끼워 넣기), `noise_turn`(주변 대화), `allergy_have`/`allergy_none`, 결제 실수(`method_early`, `page_nav`, `phone_skipped`) |
| `backend/tools/voice_scenario_suite.py` | `--random N --seed S --tier 사람처럼 --human 1`, `--category 회귀`(G01~G13: 대화 로그의 실제 실패 사례), `--category 대량`(고정 100개) |
| `backend/tools/suite_metrics.py` | 연쇄 실패를 걷어낸 **이어가기 판정**(PASS/SOFT/FAIL), 턴당 첫 실패율, 조작별 Wilson 95% 구간, 응답 시간 |
| `backend/tools/persona_sim.py` | LLM이 연기하는 손님(할머니, 급한직장인, 말많은손님, 알레르기부모, 마음바꾸는손님, 외국인, 진상)이 목표 주문을 끝까지 주문. **아직 한 번도 실행하지 않음** |

판정 방식: 정답은 매 턴 서버 장바구니가 기대값과 정확히 같은지 보는 것입니다. 한 번 어긋나면 이후 턴이 모두 실패로 잡혀 숫자가 부풀려지므로,
이어가기 판정은 앞에서 생긴 불일치를 쌓아 두고 **새로 생긴 불일치만** 그 턴의 실패로 셉니다. 엄격 판정 숫자도 함께 출력합니다.
`SOFT`는 교체에서 A만 지우고 B를 되묻는 응답(삭제 후 확인)입니다.

### 실행 방법 (backend 폴더, 서버가 떠 있어야 함. 포트는 환경에 맞게 `--url`)
```
python tools/voice_scenario_suite.py --url http://localhost:8000 --category 회귀
python tools/voice_scenario_suite.py --url http://localhost:8000 --random 50 --seed 20261026 --tier 사람처럼 --human 1 --workers 4
python tools/voice_scenario_suite.py --url http://localhost:8000 --category 대량 --workers 4
python tools/voice_scenario_suite.py --random 10 --seed 7 --tier 사람처럼 --human 2 --dry-run   # 발화만 확인 (LLM 비용 0)
python tools/persona_sim.py --count 4 --dry-run                                                   # 목표/프롬프트 확인
```
단위 테스트: 환경의 site-packages에 `tests` 패키지가 있어 프로젝트 `tests`를 가립니다. `tests` 패키지 경로를 덮어쓴 임시 러너로 실행했습니다.

## 3. 측정 결과

### 3-1. 음성 검증 50개 (사람처럼 티어, seed 20261026, `--human 1`)
| 지표 | 수정 전 | 수정 후 |
|---|---|---|
| 시나리오 통과 | 14/50 (28%) | **49/50 (98%)** |
| 턴당 첫 실패율 | 6.9% (36/518) | **0.1%** (1/723) |
| `change_mind` 실패 | 31/48 | 0/48 |
| `set_qty` 실패 | 5/6 | 0/6 |
| `pay_phone` 실패 | 5/19 | 0/20 |
| 응답 시간 p50 / p90 | 4.6s / 6.7s | 4.2s / 6.0s |

수정 후 실행에서 교체 48번, 수량 변경 6번을 코드 경로가 처리했습니다.
남은 실패 1건(R36): "더블치즈버거 하나 줘" → 되묻는 중 "단품으로 줘"에서 장바구니가 비어 있음. 원인 미확인.

### 3-2. 고정 100개 (W001~W100)
- 통과 **99/100**, 1,122턴, 약 41분(4개 병렬), 턴당 첫 실패율 0.1% (1/1,119), 응답 p50 4.3s / p90 6.0s / 최대 12.9s.
- 실패 1건(W060, 세트 옵션): "그릴드비프버거 세트로 하나 줘" → 사이드 → 음료 순서에서 앞 두 턴은 "아직 담지 못했어요"(`reply_without_action`), 마지막 턴은 "세트 1개 담았습니다"라고 답했지만 실제 장바구니에는 **생수 단품만** 들어감. 서버가 말과 실제가 어긋난 사례입니다.
- 이 세트는 수정 전에 측정하지 않아 전후 비교는 없습니다.

### 3-3. 이 수치를 읽을 때 주의
- 3-1의 수정은 첫 측정에서 실패한 **같은 시드**를 보고 만들었습니다. 수정 후 98%는 그 시드에서의 점수이며 일반화된 성능이 아닙니다. 다른 시드로 다시 확인해야 합니다.
- 생성기를 일부 바꿔(이미 단품이 담긴 버거에 "세트로 하나 줘"처럼 사람도 해석이 갈리는 말은 만들지 않음) 두 번째 측정의 시나리오는 첫 측정과 100% 같지 않습니다.
- 두 세트 모두 정해진 문장 틀에 군말을 얹은 것이라 실제 손님의 자유로운 말은 반영하지 못합니다. 마이크 게이트·VAD·실제 STT 오인식도 검증하지 않습니다(텍스트를 서버에 바로 보냄).
- 조작별 표본이 작아 0/6 같은 값의 95% 상한은 39%입니다.
