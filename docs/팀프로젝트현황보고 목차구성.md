### 1.2 프로젝트 최종 목표

#### 프로젝트의 최종 산출물

LLM 기반 음성 대화 + 컴퓨터 비전(CV) 기반 제스처 인식을 결합한 **배리어프리 버거 키오스크 웹 앱 시스템**

구성 요소:
- **키오스크 프론트엔드**: React 기반 터치/음성/제스처 지원 12화면 키오스크 UI
- **백엔드 API 서버**: FastAPI 기반 REST + WebSocket 서버
- **AI 모듈**: STT, LLM 에이전트, TTS, 제스처 분류기, 흰 지팡이 감지기
- **관리자 대시보드**: JWT 인증 기반 별도 관리자 웹 UI
- **데이터베이스**: MySQL + SQLAlchemy ORM

#### 핵심 기능

| 번호 | 핵심 기능 | 설명 |
|------|-----------|------|
| 1 | 지능형 음성 대화 주문 | Whisper STT → GPT-4o-mini LangChain 에이전트 → TTS 스트리밍 |
| 2 | 비접촉 제스처 제어 | MediaPipe Hands → MLP 분류기 → WebSocket → UI 이벤트 |
| 3 | 시각장애인 접근 자동 감지 | YOLOv8 INT8 TFLite → 흰 지팡이 감지 → 음성 안내 TTS |
| 4 | 다국어 지원 | 한국어 / 영어 / 중국어(간체) / 일본어 실시간 전환 |
| 5 | 관리자 통합 운영 시스템 | 메뉴/주문/쿠폰/할인/통계/회원 관리 |

#### AI 적용 목표

| AI 기술 | 적용 목적 | 사용 모델/라이브러리 |
|---------|-----------|---------------------|
| Speech-to-Text | 자연어 음성 입력 → 텍스트 변환 | OpenAI Whisper (gpt-4o-mini-transcribe) |
| LLM Agent | 자연어 이해, 주문 처리, 메뉴 추천 | GPT-4o-mini + LangChain AgentExecutor |
| RAG | 메뉴 정보 기반 검색 증강 | FAISS + text-embedding-3-small |
| Text-to-Speech | 음성 안내, 시각장애인 지원 | OpenAI TTS (tts-1, alloy) |
| 손 제스처 인식 | 비접촉 UI 조작 | MediaPipe Hands + scikit-learn MLP |
| 객체 감지 | 흰 지팡이 접근 자동 감지 | YOLOv8 INT8 TFLite |

## 2. 1학기 분석·설계 결과와 변경사항

### 2.1 1학기 주요 설계 결과

#### 시스템 구성도 (Phase 1 기준)

```
[사용자]
  ↓ 터치 / 음성 / 제스처
[키오스크 프론트엔드 (React)]
  ↓ REST API / WebSocket
[백엔드 서버 (FastAPI)]
  ├── STT 모듈 (Whisper)
  ├── LLM 모듈 (LangChain + GPT)
  ├── TTS 모듈 (OpenAI TTS)
  └── CV 모듈 (MediaPipe)
```

#### 주요 기능 정의 (1학기 설계)

| 기능 | 설계 내용 |
|------|-----------|
| 음성 주문 | Whisper STT + GPT 기반 자연어 주문 처리 |
| 제스처 인식 | MediaPipe Hands 21포인트 + MLP 분류기 |
| 다국어 지원 | 한/영/중/일 4개 언어 |
| 터치 주문 | 12개 화면 플로우 (메뉴 → 장바구니 → 결제 → 완료) |
| 데이터베이스 | 메뉴, 주문, 사용자, 결제 테이블 설계 |

#### 데이터 및 AI 모델 설계

- **STT**: OpenAI Whisper API (`whisper-1` → 이후 `gpt-4o-mini-transcribe`로 업그레이드)
- **LLM**: OpenAI GPT (`gpt-4o-mini`) + LangChain ReAct 에이전트
- **제스처 모델**: MediaPipe Hands 21포인트 → 정규화 → MLP 분류
- **대화 메모리**: LangChain `ConversationSummaryBufferMemory` (max 800 토큰)

#### UI/UX 및 서비스 구조

- 화면 플로우: 시작 → 주문방식 선택 → 메뉴 → 장바구니 → 결제(카드/현금/Pay) → 완료
- 채팅 패널: 음성 대화 표시 + 텍스트 입력 병행
- 관리자 화면: 기본 메뉴 관리만 설계 (Phase 2에서 대폭 확장)

### 2.3 현재 시스템 구성

#### 현재 기준 시스템 아키텍처

```
[사용자 / 관리자]
     ↓
[React 프론트엔드 (Vite 개발 서버 / Cloudflare Tunnel)]
  ├── 키오스크 UI (12개 화면)
  ├── 채팅 패널 (음성/텍스트)
  └── 관리자 대시보드 (JWT 인증)
     ↓ REST API + SSE + WebSocket
[FastAPI 백엔드 서버 (포트 8000)]
  ├── /ai_modules/stt          ← Whisper STT
  ├── /ai_modules/llm/stream   ← LangChain SSE 스트리밍
  ├── /ai_modules/tts          ← OpenAI TTS
  ├── /ws/gesture              ← MediaPipe 제스처 WebSocket
  ├── /ws/approach             ← 흰 지팡이 감지 WebSocket
  ├── /menu, /cart, /order, /payment, /discounts
  └── /admin/*                 ← 관리자 CRUD API
     ↓
[MySQL DB (kiosk_db)]          [OpenAI API]          [FAISS 인메모리]
```

#### 프론트엔드 구성

| 구분 | 내용 |
|------|------|
| 프레임워크 | React 18.3.1 + Vite 5.4.1 |
| 화면 수 | 12개 (`StartScreen`, `MenuScreen`, `CartScreen`, `PaymentScreen` 등) |
| 주요 훅 | `useGesture.js`, `useApproachDetector.js`, `useIdleTimer.js` |
| 다국어 | `i18n/translations.js` (한/영/중/일, `LocaleContext`) |
| CV 라이브러리 | `@mediapipe/hands`, `onnxruntime-web` |
| 음성 감지 | `@ricky0123/vad-react` (Voice Activity Detection) |
| QR 스캔 | `@zxing/browser`, `@zxing/library` |

#### 백엔드 및 데이터베이스 구성

| 구분 | 내용 |
|------|------|
| 프레임워크 | FastAPI + Uvicorn |
| ORM | SQLAlchemy 2.0 (비동기, aiomysql) |
| DB | MySQL (`kiosk_db`) |
| 인증 | JWT (`python-jose`) + bcrypt |
| API 레이어 | `api/` 라우터 + `core/` 서비스 + `dao/` 데이터 접근 + `schemas/` Pydantic |

#### AI 모델 및 외부 API 연계 구조

| AI 기능 | 연계 방식 | 모델/서비스 |
|---------|-----------|------------|
| STT | REST POST | OpenAI `gpt-4o-mini-transcribe` |
| LLM | SSE 스트리밍 | OpenAI `gpt-4o-mini` + LangChain |
| TTS | REST POST → MP3 반환 | OpenAI `tts-1` (alloy) |
| RAG | 인메모리 FAISS | `text-embedding-3-small` |
| 정적 제스처 | WebSocket (실시간 추론) | scikit-learn MLP (joblib) |
| 동적 제스처 | WebSocket (실시간 추론) | scikit-learn MLP (joblib) |
| 흰 지팡이 감지 | WebSocket (실시간 추론) | YOLOv8 INT8 TFLite |

### 4.2 핵심 기능 구현 결과

#### 핵심 기능 1: 지능형 음성 대화 주문

```
[마이크 입력]
    ↓ VAD (Voice Activity Detection, @ricky0123/vad-react)
[음성 구간 자동 감지]
    ↓ JPEG → WebM Blob
[POST /ai_modules/stt]
    ↓ OpenAI Whisper (gpt-4o-mini-transcribe) + 메뉴 어휘 힌트
[텍스트 출력 + 언어 자동 감지]
    ↓
[POST /ai_modules/llm/stream (SSE)]
    ↓ LangChain AgentExecutor (max_iterations=8)
    ↓ 11개 툴 실행 (add_item, navigate, ui_action 등)
    ↓ FAISS RAG 메뉴 검색
[SSE 토큰 스트리밍 + 액션 이벤트]
    ↓
[POST /ai_modules/tts → MP3 → 브라우저 재생]
```

구현 상태:
- 4개 언어 자동 감지 및 언어별 응답
- 환각 방지: 결제 우회로 코드 레벨 차단, 환각 패턴 감지
- LLM 대화 메모리: 세션별 `ConversationSummaryBufferMemory` (800 토큰)
- JSONL 대화 로그 자동 기록

#### 핵심 기능 2: 비접촉 제스처 인식

```
[웹캠 영상]
    ↓ @mediapipe/hands (브라우저 내 추론)
[손 관절 21개 포인트 추출]
    ↓ WebSocket /ws/gesture (JPEG 프레임 전송)
[정적 MLP 분류기 (128→64→32)]
    → ok, none, pointing 등
[동적 MLP 분류기 (86차원 특징)]
    → swipe_left, swipe_right, none
[분류 결과 → 브라우저 이벤트 발송]
    ↓
[화면 스크롤, 메뉴 선택, 수량 조절 등 UI 제어]
```

구현 상태:
- 정적/동적 제스처 분류 모델 분리 운영
- 브라우저 내 MediaPipe Hands 추론 후 서버 MLP로 최종 분류
- useGesture.js (31KB) 훅에서 제스처 이벤트 관리

#### 핵심 기능 3: 흰 지팡이 접근 자동 감지

```
[웹캠 영상]
    ↓ WebSocket /ws/approach (JPEG 바이너리)
[YOLOv8 INT8 TFLite 추론 (best_int8.tflite)]
    ↓ WHITE_CANE_CLASS_ID=1, 신뢰도 0.5 이상
[상태 머신: IDLE → VOICE_MODE]
    ↓ 10초마다 최대 3회 TTS 안내
["햄버거 주문을 위한 키오스크 입니다." 음성 재생]
    ↓ MP3 메모리 캐시 (첫 1회만 TTS 생성)
[사용자 터치 시 → IDLE 복귀]
```

구현 상태:
- asyncio.Lock으로 추론 직렬화 (동시 접근 방지)
- asyncio.to_thread로 동기 TFLite 추론 오프로드
- 최초 TTS 생성 후 메모리 캐시로 반복 재생

| 모델 | 분할 방식 |
|------|-----------|

- 기본 증강: x6배 (ok/none 클래스는 x10배)

- z축 회전: ±12°
- y축 회전: ±8°

**동적 제스처 증강** (`train_dynamic.py`):
- x축 미러: swipe_left ↔ swipe_right 레이블 교환

## 6. 시스템 통합 및 실행 결과

### 6.1 시스템 통합 현황

#### 프론트엔드-백엔드 연동

| 연동 방식 | 사용 목적 | 구현 상태 |
|-----------|-----------|-----------|
| REST API (HTTP/HTTPS) | 메뉴/장바구니/주문/결제/관리자 CRUD | ✅ 완료 |
| Server-Sent Events (SSE) | LLM 토큰 스트리밍 + 액션 이벤트 실시간 전달 | ✅ 완료 |
| WebSocket | 제스처 인식 실시간 스트리밍 | ✅ 완료 |
| WebSocket | 흰 지팡이 접근 감지 실시간 스트리밍 | ✅ 완료 |

#### AI 모델-서비스 연동

| AI 모듈 | 연동 포인트 |
|---------|------------|
| STT | `backend/core/stt_service.py` → `backend/api/stt.py` |
| LLM | `ai_modules/llm/agent.py` → `backend/core/llm_service.py` (SSE) |
| TTS | `backend/core/tts_service.py` (LLM 완료 이후 자동 호출) |
| RAG | `ai_modules/llm/rag.py` (LLM 에이전트 내부에서 `search_menu` 툴로 호출) |
| 제스처 MLP | `ai_modules/cv/gesture_classifier.py` → `backend/api/gesture_ws.py` |
| 흰 지팡이 TFLite | `ai_modules/cv/approach_detector.py` → `backend/api/approach_ws.py` |

#### 데이터베이스/API 연동

- MySQL (`kiosk_db`) ↔ SQLAlchemy ORM ↔ DAO 레이어 ↔ 서비스 레이어 ↔ FastAPI 라우터
- RAG 캐시: 메뉴 변경 시 `invalidate_cache()` 호출 → FAISS 인덱스 재빌드
- 활성 할인 정보: `get_active_discount_context()` → LLM 프롬프트 자동 주입

#### 전체 시스템 통합 수준

- 키오스크 기본 플로우: **통합 완료** (음성+터치+제스처 → 주문 → 결제)
- 관리자 시스템: **통합 완료** (JWT 인증 + CRUD + 통계)
- 흰 지팡이 감지: **통합 완료** (WebSocket + 상태 머신 + TTS 안내)
- 할인/쿠폰: **통합 완료** (DB 기반 할인 계산 + 키오스크 화면 실시간 반영)

### 9.2 연구 방법

#### 데이터 수집 방법

- 제스처 데이터: MediaPipe Hands 기반 직접 수집 및 증강
- 사용자 실험: 고령자/시각장애인 대상 사용성 평가 (System Usability Scale, SUS)
- LLM 평가: 정의된 시나리오 기반 자동화 테스트

#### 실험 설계

| 실험 | 내용 |
|------|------|
| LLM 시나리오 테스트 | 15개 이상 시나리오 통과율 측정 |
| 제스처 인식 정확도 | 정적/동적 제스처 분류 정확도 (F1-score) |
| 사용자 사용성 평가 | SUS 설문 기반 사용 편의성 측정 |
| 흰 지팡이 감지 성능 | 환경별(조도/각도) 감지율 측정 |

#### 비교 방법

- LLM 응답 품질: 규칙 기반 주문 처리 vs. LLM 에이전트 방식 비교
- 접근성: 기존 터치 전용 vs. 음성+제스처 통합 키오스크 사용성 비교

#### 평가 지표

| 항목 | 지표 |
|------|------|
| LLM 시나리오 통과율 | 통과 시나리오 수 / 전체 시나리오 수 |
| 제스처 인식 정확도 | F1-score, Confusion Matrix |
| STT 인식률 | WER (Word Error Rate) |
| 흰 지팡이 감지율 | Precision / Recall @ IoU 0.5 |
| 사용성 | SUS 점수 (0~100) |
| 시스템 응답 속도 | STT+LLM+TTS 전체 응답 시간 (ms) |
