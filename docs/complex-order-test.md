# 복잡 주문 시나리오 테스트 (17턴)

> 작성일: 2026-05-31
> 사용자가 제시한 17턴 실제 대화로 전체 흐름을 검증하고 발견된 문제를 수정한 기록.
> 모델: gpt-4o-mini. 매 턴 액션을 적용해 장바구니/화면/주문유형 상태를 갱신(프론트와 동일하게 cart_id 기반 매칭).

---

## 입력 대화

```
Q1  안녕하세요
Q2  매장
Q3  추운데 추천 메뉴 있어?
Q4  F버거 세트로 줘
Q5  감자튀김
Q6  콜라
Q7  콜라는 살 찔것 같아. 그냥 생수로 변경해줘.
Q8  F버거 세트에 치즈스틱, 제로 사이다로 된것 추가로 3개 더 담아줘.
Q9  단품으로 치킨너겟 3개 담아줘.
Q10 아까 F버거 생수 세트 시킨거, 양상추 빼줘.
Q11 치킨다릿살버거 하나 단품으로 시켜줘.
Q12 아니다 치킨 다릿살 버거도 세트로 시켜줘.
Q13 그냥 콜라에, 치즈스틱
Q14 결제 진행해
Q15 포인트 적립할꺼야.
Q16 01012345678
Q17 카드로 결제할게.
```

## 발견 → 수정 완료한 문제

| 문제 | 수정 내용 |
|------|----------|
| "콜라 하나"에 단품/세트 되물음 | 사이드(13~16)·음료(17~23)는 항상 단품, 세트 질문 금지 명시 |
| "세트 주세요" 시 옵션 안 묻고 기본값 담김 | 버거 세트는 사이드+음료 모두 확정 전 add_item 금지 (STEP화) |
| 세트 후 "치킨너겟이요"를 별개 메뉴로 오해 | "세트 질문 후 답변은 진행 중 세트 옵션"으로 인식 |
| "콜라 두 개" → 1개 | 수량 파싱 규칙 강화 (모든 메뉴 공통) |
| **같은 메뉴 여러 줄 식별 불가** (엉뚱한 줄 삭제) | **cart_id 인프라 추가**: 장바구니 컨텍스트에 cart_id 노출 + remove_item/update_qty가 cart_id 인자 수용 → "생수 세트 시킨 거" 정확히 타겟팅 |
| 단품→세트 전환 시 액션 누락 | "옵션 확정 시 반드시 도구 호출, 말로만 담지 말 것" 명시 |
| **기존 항목 옵션 변경이 새 줄로 다시 담김** (Q7) | **`update_item` 도구 추가** — cart_id로 해당 줄의 옵션만 제자리 변경(위치·cart_id 유지), remove+add 금지 |
| order_type 액션 간헐 누락 | "매장/포장 의사 표현 시 order_type 필수 호출" 강화 |
| 결제 시 수단 미지정인데 자동 결제 | payment_method/points는 사용자가 명시했을 때만 호출하도록 가드 |

## 남은 한계 (gpt-4o-mini 모델 특성)

복잡한 다중 참조·상태 추적 구간에서 간헐적으로 발생하며, 프롬프트 가드로 빈도는 크게 줄었으나 완전 제거는 어려움.

1. **기존 장바구니 항목 중복 재담기 (Q8)**
   "F버거 세트에 ~ 추가로 3개 더"처럼 기존 항목을 언급하며 새로 추가하면,
   모델이 기존 줄을 한 번 더 add_item으로 재발행하는 경우가 있음.
   → "[★최우선 원칙 — 장바구니 무결성]" 가드 추가로 완화. 잔존 시 cart_id 기반 후처리 또는 상위 모델 필요.

2. **결제 다단계 상태 추적 (Q14·Q16·Q17)**
   start_checkout → points → points_phone → payment_method를 여러 턴에 나눠 진행할 때,
   - start_checkout을 늦게 발행하거나(Q14 누락)
   - 수단 미지정인데 payment_method를 임의 선택(Q16 cash 환각)
   - 이미 호출한 단계를 재호출하는 경우가 남음.
   → 가드로 완화했으나 모델이 "결제 완료"를 서두르는 경향 잔존.

### 권장 개선 방향
- **모델 상향**: `OPENAI_LLM_MODEL`을 `gpt-4o` 또는 `gpt-4.1`로 올리면 위 두 한계가 크게 개선됨 (다중 참조·상태 추적 능력 차이). 코드 변경 없이 `.env`만 수정.
- **결제 단계 프론트 위임 검토**: 결제 수단/포인트는 CartScreen의 기존 팝업 UI로 사람이 확정하게 하고, 음성은 "결제 시작"까지만 담당하면 환각 위험 제거 (원 스펙의 오결제 방지 취지와도 부합).
- **장바구니 무결성 후처리**: 프론트 `handleVoiceAction`에서 add_item 시 동일 key 중복을 병합/감지하는 가드 추가 가능.

## 결론

- 기본·중급 주문 흐름(단품/세트/옵션 단계 질문/수량/카테고리/cart_id 기반 수정·삭제/단품↔세트 전환)은 **안정적으로 동작**.
- 1차 발견 문제 8건을 수정 완료, 특히 **cart_id 기반 정확 타겟팅** 인프라를 추가해 "그 생수 세트 같은 옵션 지칭 수정"이 가능해짐.
- 남은 2개 한계(기존 항목 중복 재담기, 결제 다단계 추적)는 gpt-4o-mini의 한계로, **모델 상향 또는 결제 단계 프론트 위임**을 권장.
