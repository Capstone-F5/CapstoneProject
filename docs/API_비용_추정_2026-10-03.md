# 월 API 비용 추정 — 햄버거 매장 1곳 기준

계산식과 가정은 `backend/tools/api_cost_estimate.py`에 있고, 상수만 바꿔 다시 돌리면 된다.
**매출·연령 분포·음성 사용률은 사용자가 제공한 값이 없어 가정이다.** 실제 매장 수치를 넣어 다시 계산할 것.

## 1. 결론

| 하루 매출 | 주문 | 음성 주문(22%) | 월 비용 (캐시 80%) | 월 비용 (캐시 없음, 상한) |
|---|---|---|---|---|
| 150만원 (소형) | 167건/일 | 1,100건/월 | **약 4.8만원** | 약 6.6만원 |
| **300만원 (중형)** | 333건/일 | 2,200건/월 | **약 9.7만원** | **약 13.2만원** |
| 600만원 (대형) | 667건/일 | 4,400건/월 | 약 19.3만원 | 약 26.4만원 |

- 음성 주문 1건당 **약 44~60원**(LLM + STT + TTS). 월 매출 9,000만원(중형) 대비 0.1~0.15% 수준.
- 비용의 61~71%는 LLM이다. STT는 약 10%, TTS는 약 19~26%.
- 환율 1,400원/달러 가정. 단가는 [OpenAI 가격표](https://developers.openai.com/api/docs/pricing)(2026-10-03 확인).

## 2. 실측한 값 (이 저장소에서 측정)

| 항목 | 값 | 측정 방법 |
|---|---|---|
| LLM 호출 1회 고정 입력 | **약 10,970토큰** (시스템 프롬프트 9,146 + 도구 스키마 1,824) | `tiktoken`(o200k_base)으로 실제 프롬프트 계산 |
| 턴당 LLM 호출 수 | 1.78회 (도구 호출 1회 + 최종 응답) | 대표 주문 9턴을 `run_agent`로 실행하며 `ChatOpenAI._astream`을 가로채 집계 |
| 턴당 입력 토큰 | 약 20,500 | 위와 같음 (고정 접두가 95%) |
| 턴당 출력 토큰 | 약 100 (추정) | 스트리밍 청크로는 도구 호출 JSON이 부풀려져 정확히 못 셈. 응답 42자≈30토큰 + 도구 호출 약 60토큰으로 추정 |
| 응답 평균 길이 | 42.5자 (중앙값 38, P95 82) | 고정 100개 1,112턴 |
| 손님 발화 평균 | 12.9자 (약 3초) | 같음 |
| 주문 1건당 턴 수 | 11.1턴 | 같음 (도입부 2 + 담기 + 결제 3~4단계) |
| LLM을 거치지 않는 턴 | 21% | 직접 명령이 코드로 처리 |

주의: 토큰 수는 OpenAI 청구 사용량이 아니라 `tiktoken` 추정이다(±10% 오차 가능). 대표 주문 1건(9턴)으로 측정했다.

## 4. 음성 1턴(평균) 비용

| | 캐시 없음 | 캐시 80% |
|---|---|---|
| LLM (79%의 턴만 호출) | $0.00248 | $0.00155 |
| STT (발화 3.5초) | $0.00035 | $0.00035 |
| TTS (응답 42.5자) | $0.00064 | $0.00064 |

캐시: OpenAI는 같은 앞부분(접두)이 반복되면 입력을 반값에 처리한다. 이 서비스는 시스템 프롬프트가 매 요청 앞에 고정이라 영업 시간대에는 적중률이 높을 것으로 보지만 **실제 적중률은 측정하지 않았다.** 80%는 가정이고 손님이 뜸한 시간에는 낮아진다.

## 7. 비용을 줄이는 방법 (효과는 추정)

| 방법 | 효과 | 비고 |
|---|---|---|
| **시스템 프롬프트 줄이기** (현재 9,146토큰) | 입력의 95%가 고정 접두라서 절반으로 줄이면 LLM 비용이 약 45% 감소, 전체 약 30% | 프롬프트가 길어진 것은 규칙을 계속 덧붙였기 때문. 줄이면 가드로 옮긴 규칙부터 정리할 수 있음. 정확도 영향은 재측정 필요 |
| 캐시 적중률 높이기 | 캐시 80% 대비 없음 = 비용 약 27% 차이 | 접두를 항상 같게 유지(현재 구조는 이미 그렇다). 적중률 실측 필요 |
| 직접 처리 범위 확대 | 직접 처리 1턴은 LLM 비용 0 | 지금 21%. 재질의·세트 재료 제외 등을 코드로 옮기면 더 늘릴 수 있음 |
| STT를 `gpt-4o-mini-transcribe`로 | STT 비용 절반 (전체 약 5%) | 정확도 비교 필요 |
| 도구 스키마 축소 | 1,824토큰(고정 접두의 17%) | 화면에서 쓸 수 없는 도구를 빼는 방식 |

## 8. 한계

1. **고객·매출 수치는 모두 가정**이다. 위 결과는 "이 가정이면 이 정도"이지 예측이 아니다.
2. 토큰 수는 실제 청구가 아니라 추정이다. 실제 OpenAI 사용량 대시보드와 비교해 보정할 것.
3. 시나리오 기반 대화 길이(11.1턴)는 실제 손님과 다를 수 있다. 실제 대화 로그(`backend/logs/conversations`)로 재계산하는 것이 좋다.
4. 제외한 비용: 대화 요약 메모리의 LLM 호출(대화가 길어질 때 가끔 발생), 임베딩, 서버·네트워크·전기, 오류 재시도, 인식 실패로 인한 재발화. 모두 합쳐도 몇 % 수준으로 보이나 측정하지 않았다.
5. 지팡이·휠체어 감지는 서버 로컬 추론(`ai-edge-litert`)이라 API 비용이 없다.

## 9. 추가 시나리오: 음성 이용자를 "60대 이상 조작 어려움 계층 + 시각장애인"으로 한정

### 9.1 근거 수치와 정의 (출처 확인)

| 수치 | 값 | 정의 (원문 확인) |
|---|---|---|
| **60대 이상 '조작 어려움' 53.6%** | 53.6% | 한국소비자원 **2022년 7월** 키오스크 이용 실태조사. 키오스크 이용 경험이 있는 20~60대 500명(연령별 100명) 중, 불편·피해를 경험한 60대 이상 응답자가 **복수응답으로 '조작 어려움'을 꼽은 비율**. "60대 이상 전체의 53.6%가 조작이 어렵다"가 아니다. 이용 경험이 없는 사람은 표본에서 빠져 있다 |
| 같은 조사의 전체 불편·피해 경험률 | 46.6% (233/500) | 60대 이상만의 불편 경험률은 확인하지 못했다 |
| (다른 조사의 같은 숫자) | 53.6% | 2025년 NIA 조사에서 70대 이상의 디지털정보화 수준이 일반 국민의 53.6% — 위 지표와 무관 |
| 등록 시각장애인 | **약 24.8만 명** | 보건복지부 2023년 등록장애인 현황: 등록장애인 2,641,896명(인구의 5.1%) 중 시각장애 9.4% |
| 시각장애인 비율 | **약 0.48%** | 24.8만 ÷ 약 5,180만 명(5.1%에서 역산). **등록 기준**이라 저시력·미등록자는 빠져 있고 실제는 더 높다 |
| 65세 이상 시각장애인 | 약 14만 명(56%) | 65세 이상 등록장애인 1,425,095명 × 시각장애 비율 9.8%로 계산 → 고령층과 일부 겹침(고령 인구에 비해 매우 작아 무시) |

사용자가 제시한 "2023년 기준"과 달리 출처는 2022년 조사이다.

### 9.2 가정 (실측 아님)

- 60대 이상 방문객 비중 10%(앞 절 가정 유지), 시각장애인 방문객 비중은 인구 비율과 같은 0.48%로 가정(방문 빈도는 더 낮을 수 있음).
- 음성 사용률: **A** 60대 이상의 53.6% × 20% = **10.72%**(요청 기준, 53.6%를 60대 이상 전체의 비율로 해석), **B** 엄밀 해석 = 불편 경험률 46.6%(전체 평균 대용) × 53.6% × 20% = **5.0%**, **C** 시각장애인 80%, **D** 시각장애인 100%.
- 주문당 16.6턴(11.1턴 × 고령 배수 1.5), 음성 주문 1건 비용 59원(캐시 80%) ~ 81원(캐시 없음). 영업 12시간, 점심·저녁 4시간에 주문의 50%.

### 9.4 해석

- 음성 이용자를 이 두 계층으로 한정하면 **하루 3~10건, 월 API 비용은 매출 규모와 무관하게 몇천 원~2만원대**이다(앞 절 22% 가정의 월 13만원과 큰 차이).
- 피크 시간당 0.3~1.2건이라 동시 처리는 문제가 되지 않는다.
- 비용보다 중요한 것은 **이 소수 사용자에게 정확하게 동작하는지**다. 하루 5건 안팎이면 한 건의 실패가 전체 이용자의 20%에 해당한다.
- 절감 방법(7절)은 이 규모에서는 금액상 의미가 거의 없다. 시각장애인·고령자는 음성이 유일한 수단이므로 정확도와 응답 지연을 우선하는 것이 맞다.
- 한계: 고령층 방문 비중, 시각장애인 방문율, 20% 이용률은 모두 가정이다. 53.6%의 해석(A/B)에 따라 음성 주문이 약 40% 차이 난다.
