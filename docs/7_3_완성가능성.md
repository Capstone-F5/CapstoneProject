# 7.3 현재 프로젝트의 완성 가능성

---

## 남은 핵심 개발 항목

| 우선순위 | 항목 | 예상 소요 | 담당 |
|:---:|---|---|---|
| 🔴 높음 | 하드웨어 출력·조립 완성 (현재 60%) | 1~2주 | 조예성 |
| 🔴 높음 | HW-SW 통합 연결 및 동작 테스트 | 3~5일 | 전체 |
| 🟡 중간 | 손가락 수 수량 선택 UI 연동 (#64) | 2~3일 | 조예성 |
| 🟡 중간 | 알레르기 관리자 UI 구현 (#63) | 1~2일 | 진수민 |
| 🟢 낮음 | 음성 인식 첫 응답 지연 개선 (#46) | 1일 | 김성원·임지연 |
| 🟢 낮음 | 기타 잔여 이슈 (할인 중복·멤버십 등) | 각 0.5~1일 | 분산 |

---

## 기술적으로 해결해야 할 사항

### 손동작 수량 선택 UI
카메라가 키오스크 HW에 최종 고정된 위치를 기준으로 인식 좌표계를 재설정해야 한다.  
이후 손가락 클래스(1~5) 결과를 수신하는 팝업 UI를 키오스크 화면에 연동해야 한다.  
→ **HW 조립 완료 전에는 착수 불가한 순차 의존 구조**

### HW-SW 통신 연결
키오스크 본체(라즈베리파이 또는 임베디드)와 기존 FastAPI 서버 간 카메라 스트림 및 제스처 결과 전달 방식을 실물 기준으로 최종 확정해야 한다.  
→ 현재 WebSocket 기반 구조 준비 완료, HW 실물 테스트만 남음

### 통합 테스트 미검증 엣지케이스
음성 주문 + 제스처 수량 선택 + 결제가 동시에 동작할 때의 동시성 충돌 여부가 실물 환경에서 아직 미검증 상태다.

## 일정상 위험 요소

| 위험 요소 | 영향 | 대응 방안 |
|---|---|---|
| 3D 프린팅 출력 지연 | HW 조립·통합 테스트 전체 지연 | 출력 우선 처리, 병렬로 SW 잔여 이슈 해결 |
| HW 의존성 체인 | 손동작 UI → HW 확정 → 통합 테스트 순으로 묶임 | HW 완성을 최우선 목표로 집중 |
| 통합 테스트 시간 부족 | 발표 직전 버그 발생 시 수정 시간 없음 | 기능 단위 개별 테스트를 먼저 진행 |
| 잔여 이슈 10건 | 발표 완성도에 영향 | 우선순위 낮은 이슈는 발표 후 처리로 분류 |

## 최종 완성 가능성 자체 평가

| 영역 | 현재 완성도 | 발표 시점 예상 완성도 | 판단 |
|---|:---:|:---:|---|
| SW 기능 전체 | 95% | **98%** | 거의 완성, 잔여 이슈만 정리 |
| AI 모델 및 연동 | 97% | **97%** | 완성 상태 유지 |
| 하드웨어 제작 | 70% | **90%** | 출력·조립 기간 내 완료 가능 |
| HW-SW 통합 | 10% | **80%** | HW 완성 직후 빠른 연동 가능 |
| **전체 종합** | **~75%** | **~92%** | **발표 기준 완성 가능** |

### 종합 의견

핵심 AI 기능(음성 주문, 제스처 인식, 취약계층 감지, 다국어 대응)은 이미 완성 수준이며, 관리자 시스템·배포 환경도 안정적으로 동작한다.  
**발표 완성도를 좌우하는 변수는 하드웨어 조립 완료 시점**이다. 조립이 9월 2주차 내에 완료된다면 통합 테스트 및 잔여 이슈 해결에 충분한 시간이 확보되며, **발표 기준 목표 기능의 90% 이상 시연이 가능하다**고 판단한다.
