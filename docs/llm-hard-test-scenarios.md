# 음성 주문 AI — 까다로운 테스트 시나리오

> 작성일: 2026-05-31
> 목적: 실제 사용 중 발견된 엣지케이스 기반 품질 검증

---

## 시나리오 1 — 세트 구성 옵션 사후 변경

### 배경
세트 메뉴의 사이드나 음료는 담을 때 확정된다.
담은 뒤 "음료 바꿔줘"는 현재 도구 구조상 `remove_item + add_item` 조합이 필요하다.
이때 AI가 올바른 도구를 순서대로 호출하는지, UI에 반영되는지 검증한다.

### 전제 조건
```
screen: cart
order_type: dine-in
cart: [
  { menu_id: 4, name: "새우버거", item_type: "set",
    quantity: 1, unit_price: 6800,
    side: "양념감자튀김", drink: "오렌지주스" }
]
```

### 대화 흐름

| 턴 | 사용자 | 기대 AI 응답 | 기대 액션 |
|----|--------|------------|---------|
| 1 | 새우버거 세트 음료를 콜라로 바꿔줘 | "새우버거 세트 음료를 콜라로 변경했습니다." | `remove_item(menu_id=4)` → `add_item(menu_id=4, item_type=set, side=양념감자튀김, drink=콜라)` |
| 2 | 이번엔 사이드도 감자튀김으로 바꿔줘 | "새우버거 세트 사이드를 감자튀김으로 변경했습니다." | `remove_item(menu_id=4)` → `add_item(menu_id=4, item_type=set, side=감자튀김, drink=콜라)` |

### 검증 포인트
- [ ] `remove_item` 후 `add_item` 순서대로 발행되는가
- [ ] `add_item`에서 변경하지 않은 옵션(사이드)이 기존값 유지되는가
- [ ] UI 장바구니가 즉시 반영되는가 (메뉴 화면 하단 미니 카트 포함)
- [ ] AI가 복창하는 내용이 실제 UI와 일치하는가

### 알려진 문제
- AI가 "변경했습니다"라고 말하지만 실제 액션이 발행되지 않는 경우 있음
- 변경 후 AI의 다음 발화에서 참조하는 cart 상태가 변경 전 스냅샷일 수 있음

## 시나리오 2 — 두 세트의 동일 옵션 동시 변경

### 배경
장바구니에 세트 메뉴가 여러 개일 때 한 발화로 "다 바꿔줘"를 처리하는 능력을 검증한다.
각 항목의 `cartId`가 다르므로 AI가 올바른 `match`로 각각 처리해야 한다.

### 전제 조건
```
screen: cart
order_type: dine-in
cart: [
  { menu_id: 4, name: "새우버거", item_type: "set",
    quantity: 1, side: "양념감자튀김", drink: "오렌지주스" },
  { menu_id: 1, name: "F버거", item_type: "set",
    quantity: 1, side: "감자튀김", drink: "뽀로로음료" }
]
```

### 대화 흐름

| 턴 | 사용자 | 기대 AI 응답 | 기대 액션 |
|----|--------|------------|---------|
| 1 | 두 세트 음료 다 콜라로 바꿔줘 | "두 세트 음료를 모두 콜라로 변경했습니다." | 새우버거: `remove+add(drink=콜라)`, F버거: `remove+add(drink=콜라)` — 총 4개 액션 |
| 2 | 새우버거 세트만 음료 빼줘 | "새우버거 세트는 세트 구성에 음료가 포함되어 있어 삭제할 수 없습니다. 다른 음료로 변경할까요?" | 액션 없음, 안내만 |
| 3 | 그럼 새우버거 아예 삭제해 | "새우버거 세트를 삭제했습니다." | `remove_item(menu_id=4)` |

### 검증 포인트
- [ ] 두 항목을 독립적으로 처리하는가 (한 번에 4개 액션 발행)
- [ ] 턴 2에서 "음료 단독 삭제 불가" 안내가 정확한가
- [ ] 턴 3 이후 장바구니에 F버거 세트만 남는가

## 시나리오 3 — 비교 기반 간접 선택

### 배경
사용자가 메뉴 이름 대신 "가장 싼 거", "두 번째로 비싼 거" 등 비교 표현으로 주문한다.
AI가 카탈로그 데이터를 기반으로 올바르게 해석하고 담는지 검증한다.

### 전제 조건
```
screen: menu
order_type: dine-in
cart: []
```

### 대화 흐름

| 턴 | 사용자 | 기대 AI 응답 | 기대 액션 |
|----|--------|------------|---------|
| 1 | 버거 중에 가장 저렴한 걸로 세트 주세요 | "데리버거가 4,000원으로 가장 저렴합니다. 데리버거 세트로 담을게요. 사이드는 뭐로 드릴까요?" | 질문 후 add_item 대기 |
| 2 | 사이드는 추가 금액 없는 걸로, 음료는 가장 비싼 걸로 | "사이드는 감자튀김으로, 음료는 오렌지주스(+500원)로 담겠습니다." | `add_item(menu_id=8, item_type=set, side=감자튀김, drink=오렌지주스)` |
| 3 | 사이드 중에서 제일 비싼 걸로 바꿔줘 | "양념감자튀김(+500원)으로 변경했습니다." | `remove_item(menu_id=8)` → `add_item(menu_id=8, item_type=set, side=양념감자튀김, drink=오렌지주스)` |

### 검증 포인트
- [ ] 카탈로그 가격 기반으로 올바른 메뉴를 선택하는가
  - 가장 저렴한 버거: 데리버거 4,000원
  - 가장 비싼 음료: 오렌지주스 +500원
  - 가장 비싼 사이드: 양념감자튀김 +500원
- [ ] "추가 금액 없는 것"을 extra=0으로 올바르게 해석하는가
- [ ] 비교 선택 결과를 발화 전에 복창하는가

## 시나리오 4 — 주문 중단 및 전면 재시작

### 배경
주문 도중 마음이 바뀌어 처음부터 다시 하는 흐름을 검증한다.
`clear_cart` 후 주문 유형까지 초기화할지 여부, 대화 맥락 처리를 확인한다.

### 전제 조건
```
screen: menu
order_type: dine-in
cart: [
  { menu_id: 5, name: "치즈버거", item_type: "set", quantity: 2,
    side: "치킨너겟", drink: "콜라" },
  { menu_id: 13, name: "감자튀김", item_type: "single", quantity: 1 }
]
```

### 대화 흐름

| 턴 | 사용자 | 기대 AI 응답 | 기대 액션 |
|----|--------|------------|---------|
| 1 | 다 취소하고 처음부터 다시 할게 | "장바구니를 모두 비웠습니다. 처음부터 주문하겠습니다. 어떤 메뉴를 원하시나요?" | `clear_cart` |
| 2 | 잠깐, 치즈버거 세트는 살려줘 | "죄송합니다. 이미 장바구니를 비워서 치즈버거 세트가 없습니다. 다시 담아드릴까요?" | 액션 없음, 안내만 |
| 3 | 응, 치즈버거 세트 두 개, 치킨너겟이랑 사이다로 | "치즈버거 세트 2개 담았습니다. 사이드 치킨너겟, 음료 사이다입니다." | `add_item(menu_id=5, quantity=2, side=치킨너겟, drink=사이다)` |
| 4 | 아까랑 똑같이 해줘 | "기억하고 있는 이전 주문은 없습니다. 어떤 메뉴로 담아드릴까요?" | 액션 없음, 안내 (메모리 한계) |

### 검증 포인트
- [ ] `clear_cart` 후 AI가 빈 장바구니를 인지하는가
- [ ] 턴 2에서 없는 항목 복구 불가를 정확히 안내하는가
- [ ] "아까랑 똑같이" 같은 기억 의존 요청을 graceful하게 처리하는가

## 시나리오 5 — 금액 계산 + 부분 삭제 + 결제 흐름

### 배경
복잡한 장바구니 상태에서 금액 질문, 특정 항목 조건부 삭제, 결제까지 이어지는 흐름을 검증한다.
AI가 컨텍스트로 받은 `unit_price × quantity` 계산 정확도도 확인한다.

### 전제 조건
```
screen: cart
order_type: takeout
cart: [
  { menu_id: 1,  name: "F버거",    item_type: "set",    quantity: 1,
    unit_price: 9500, side: "양념감자튀김", drink: "오렌지주스" },
  { menu_id: 5,  name: "치즈버거", item_type: "single", quantity: 2, unit_price: 4200 },
  { menu_id: 13, name: "감자튀김", item_type: "single", quantity: 1, unit_price: 2000 },
  { menu_id: 21, name: "생수",     item_type: "single", quantity: 3, unit_price: 1000 }
]
총합 = 9500 + 8400 + 2000 + 3000 = 22,900원
```

### 대화 흐름

| 턴 | 사용자 | 기대 AI 응답 | 기대 액션 |
|----|--------|------------|---------|
| 1 | 지금 총 얼마야? | "현재 F버거 세트 1개, 치즈버거 2개, 감자튀김 1개, 생수 3개로 총 22,900원입니다." | 액션 없음 |
| 2 | F버거 세트 빼면 얼마야? | "F버거 세트(9,500원)를 제외하면 13,400원입니다." | 액션 없음 (삭제 확인 전) |
| 3 | 그럼 빼줘 | "F버거 세트를 삭제했습니다. 총 13,400원입니다." | `remove_item(menu_id=1)` |
| 4 | 생수도 1개만 남기고 나머지 빼줘 | "생수를 1개로 변경했습니다. 총 11,400원입니다." | `update_qty(menu_id=21, quantity=1)` |
| 5 | 현금으로 결제할게 | "치즈버거 2개, 감자튀김 1개, 생수 1개 총 11,400원 결제합니다." + 결제 진행 | `start_checkout` → `points(no)` → `payment_method(cash)` |

### 검증 포인트
- [ ] `unit_price × quantity` 합산이 정확한가 (22,900원)
- [ ] "F버거 세트 빼면" = 삭제 의사가 아닌 가정 질문으로 인식하는가
- [ ] 턴 3에서 삭제 후 잔액 업데이트가 정확한가
- [ ] "1개만 남기고 나머지 빼줘" → `update_qty(quantity=1)` 정확히 처리하는가
- [ ] 최종 결제 시 복창하는 금액이 계산과 일치하는가

## 시나리오별 핵심 난이도 요소

| 시나리오 | 난이도 요소 |
|---------|-----------|
| 1 — 세트 옵션 사후 변경 | remove+add 2단계, 변경 안 한 옵션 유지, UI 동기화 |
| 2 — 다중 세트 동시 변경 | 두 항목 독립 처리, 4개 액션 순서 보장 |
| 3 — 비교 기반 간접 선택 | 카탈로그 숫자 비교, 자연어 조건 해석 |
| 4 — 전면 재시작 | clear 후 상태 인지, 복구 불가 안내, 기억 한계 처리 |
| 5 — 금액 계산 + 부분 삭제 | 합산 정확도, 가정 질문 vs 삭제 의사 구분, 조건부 수량 변경 |

## 현재 미해결 이슈 (2026-05-31 기준)

1. **세트 옵션 변경 미반영**: AI가 remove+add 액션을 발행하지만 UI 장바구니가 업데이트되지 않는 경우 있음. `resolveCartId`가 올바른 `cartId`를 찾지 못하거나 `onActionRef.current`가 stale한 상태일 가능성.

2. **AI 참조 cart와 UI cart 불일치**: AI가 이전 턴의 cart 스냅샷을 기준으로 응답하는 경우. 예: 이번 턴에서 담은 항목이 AI의 다음 발화에서 "아직 없음"으로 표시.

3. **세트 내 구성요소 단독 제거 불가 미안내**: 세트 음료/사이드는 세트 단위로만 변경 가능하나, 이를 명확히 안내하지 않고 실패하는 경우.
