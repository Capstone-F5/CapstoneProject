# AI 모델 성과 지표 (CV 모듈)

대상: `ai_modules/cv/models/` 의 모델 4종
평가일: 2026-09-29

| 파일 | 용도 | 종류 | 크기 |
|---|---|---|---|
| `best.pt` | 접근 객체 감지 (원본 가중치) | YOLOv8n, 3클래스, 입력 320×320 | 6.2 MB |
| `best_int8.tflite` | 접근 객체 감지 (라즈베리파이 배포용) | `best.pt`의 INT8 양자화본 | 3.1 MB |
| `static_mlp.pkl` | 정적 손 제스처 분류 | sklearn MLP (128-64-32) | 0.46 MB |
| `dynamic_mlp.pkl` | 동적 스와이프 제스처 분류 | sklearn MLP (128-64-32) | 0.27 MB |

## 1. 접근 객체 감지 – YOLOv8n (`best.pt`, `best_int8.tflite`)

- 클래스: `person(0)`, `white_cane(1)`, `wheelchair(2)`
- 학습: COCO `yolov8n.pt`에서 파인튜닝, 80 epoch, imgsz 320 (학습 소요 약 96분)
- 데이터: `visionguide_dataset` + `wheelchair.v5i.yolov8` 병합, wheelchair 포함 이미지 3배 오버샘플링
- 파라미터 수: 약 3.01M

### 검증 성능 (best.pt에 기록된 마지막 epoch 검증 결과, 전체 클래스 평균)

| 지표 | 값 |
|---|---|
| Precision | 0.932 |
| Recall | 0.902 |
| mAP@0.5 | **0.936** |
| mAP@0.5:0.95 | **0.747** |
| val box / cls / dfl loss | 0.813 / 0.522 / 1.011 |

- 학습 loss(box 0.661, cls 0.403, dfl 0.928)와 검증 loss가 함께 수렴했고 epoch 78~80의 mAP 변동은 ±0.001 이내입니다. 학습은 수렴한 것으로 보입니다.

### 평가의 한계 (중요)

- 검증 데이터셋(`merged_dataset`)이 저장소에 없어서 이번에 **재검증하지 못했습니다**. 위 수치는 학습 도중 기록된 값입니다.
- **클래스별 mAP는 체크포인트에 없습니다.** 특히 휠체어와 흰 지팡이는 데이터가 적어 전체 평균보다 낮을 가능성이 있습니다.
- **`best_int8.tflite`의 양자화 후 정확도는 이 저장소에서 확인할 수 없습니다.** `eval_quantized.py`로 측정할 수 있지만, 그 결과가 기록으로 남아 있지 않습니다. 배포 모델이 이 파일이므로 원본 데이터셋을 확보한 뒤 측정해 이 문서에 추가해야 합니다.
- 실제 카메라 환경(조명, 각도, 키오스크 거리)에서 현장 테스트를 한 결과도 없습니다.
- 흰 지팡이와 휠체어는 어르신·장애인 사용자 안내 기능의 트리거입니다. 오탐(false positive)·미탐(false negative)의 영향이 크므로 현장 지표가 필요합니다.

## 2. 정적 제스처 분류기 (`static_mlp.pkl`)

- 입력: MediaPipe 손 랜드마크 21점 × (x, y, z) = 63차원 (정규화)
- 클래스 7종: `finger_1`~`finger_5`, `ok`, `none`
- 데이터: 클래스당 180개(`none`, `ok`는 200개), 총 1,300개
- 평가 방법: 학습 때와 같은 분할(`train_test_split`, test 20%, `random_state=42`, stratify)로 만든 **원본 홀드아웃 260개**를 사용했습니다. 증강 데이터는 학습에만 썼습니다.

| 지표 | 값 |
|---|---|
| 홀드아웃 정확도 | **92.7%** |
| Macro F1 | 0.929 |
| 전체 데이터 정확도 (참고, 학습 샘플 포함) | 98.3% |
| 추론 시간 (PC, 1건) | 약 0.18 ms |

| 클래스 | Precision | Recall | F1 | 표본 수 |
|---|---|---|---|---|
| finger_1 | 0.946 | 0.972 | 0.959 | 36 |
| finger_2 | 1.000 | 0.944 | 0.971 | 36 |
| finger_3 | 0.972 | 0.972 | 0.972 | 36 |
| finger_4 | 0.972 | 0.972 | 0.972 | 36 |
| finger_5 | 0.923 | 1.000 | 0.960 | 36 |
| none | 0.857 | 0.750 | 0.800 | 40 |
| ok | 0.837 | 0.900 | 0.867 | 40 |

- 숫자 제스처(`finger_1`~`finger_5`)는 F1 0.96~0.97로 안정적입니다.
- **약점은 `none`↔`ok` 혼동입니다.** `none`이 `ok`로 잘못 분류된 경우가 7건(`none` 40건 중 17.5%)이었습니다. 핀치와 비슷한 손 모양을 `ok`로 오인하는 것으로 보입니다. 주문 확정 같은 동작에 `ok`를 쓰면 의도하지 않은 확정이 생길 수 있어서, 연속 프레임 다수결이나 유지 시간 조건으로 보완하는 것이 좋습니다.

## 3. 동적 제스처 분류기 (`dynamic_mlp.pkl`)

- 입력: 손 좌표 시퀀스(프레임 × 2) → 위치·속도·요약 통계 특징
- 클래스 5종: `swipe_up`, `swipe_down`, `swipe_left`, `swipe_right`, `none`
- 데이터: 클래스당 100개, 총 500개
- 평가 방법: 정적 분류기와 같은 방식으로 원본 홀드아웃 **100개**(클래스당 20개)를 사용했습니다.

| 지표 | 값 |
|---|---|
| 홀드아웃 정확도 | **91.0%** |
| Macro F1 | 0.909 |
| 전체 데이터 정확도 (참고, 학습 샘플 포함) | 98.2% |
| 추론 시간 (PC, 1건) | 약 0.16 ms |

| 클래스 | Precision | Recall | F1 | 표본 수 |
|---|---|---|---|---|
| none | 0.889 | 0.800 | 0.842 | 20 |
| swipe_down | 0.909 | 1.000 | 0.952 | 20 |
| swipe_left | 1.000 | 1.000 | 1.000 | 20 |
| swipe_right | 0.941 | 0.800 | 0.865 | 20 |
| swipe_up | 0.826 | 0.950 | 0.884 | 20 |

- `swipe_left`는 완벽하고 `swipe_down`도 recall 1.0입니다. 반면 `swipe_right`는 recall이 0.80으로 `none`(2건)과 `swipe_up`(2건)으로 새는 경우가 있습니다.
- 클래스당 검증 표본이 20개뿐이라, 정확도 1건이 1%p에 해당합니다. 신뢰구간이 넓다는 점을 감안해야 합니다.

## 4. 종합 및 한계

| 모델 | 핵심 지표 | 값 | 근거 |
|---|---|---|---|
| YOLOv8n (best.pt) | mAP@0.5 / mAP@0.5:0.95 | 0.936 / 0.747 | 학습 시 기록값 (재검증 불가) |
| YOLOv8n INT8 (tflite) | – | 미측정 | 데이터셋 부재 |
| 정적 제스처 MLP | 홀드아웃 정확도 | 92.7% | 이번 평가 (260건) |
| 동적 제스처 MLP | 홀드아웃 정확도 | 91.0% | 이번 평가 (100건) |

- 제스처 모델은 데이터를 수집한 소수 인원의 손으로 만든 것이어서, 다른 사용자에 대한 일반화 성능은 검증되지 않았습니다. 홀드아웃은 같은 수집 세션의 데이터를 무작위로 나눈 것이라 실제 성능보다 낙관적일 수 있습니다.
- 추론 시간은 개발 PC(CPU)에서 잰 값입니다. 라즈베리파이 4에서의 지연 시간은 별도로 측정해야 합니다.
- 개선 우선순위: ① INT8 양자화 후 클래스별 mAP 측정, ② `none`/`ok` 혼동 완화, ③ 다른 사용자·환경에서 제스처 검증 데이터 추가 수집.

## 재현 방법

- 제스처 모델: 저장소 데이터(`data_static`, `data_dynamic`)와 `train_static.py`/`train_dynamic.py`의 분할 조건(`test_size=0.2`, `random_state=42`)으로 같은 홀드아웃을 만들어 저장된 `.pkl`을 평가했습니다. 환경은 Python 3.13, scikit-learn 1.9.1입니다. 저장된 `.pkl`은 다른 버전으로 만들어져 sklearn 버전 경고가 나오지만 로드와 추론은 정상이었습니다.
- YOLO 모델: `ai_modules/cv/wheelchair_training/README.md`의 절차로 데이터셋을 준비한 뒤 `scripts/eval_quantized.py`, `scripts/eval_old_model.py`를 실행합니다.
